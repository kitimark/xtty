# AGENTS.md — xtty

Guidance for AI agents (and humans) working in this repository. This is the canonical project guide; `CLAUDE.md` symlinks to it.

## What this project is

**xtty** is a **native macOS terminal emulator**. It is greenfield and in the **build** phase: the app already launches a live terminal (the user's login shell in a SwiftTerm engine hosted in AppKit). The direction, requirements, and design are documented in `research/`; implementation proceeds milestone-by-milestone via the OpenSpec workflow.

**Learned refutations — do not re-propose.** Each was settled by measurement; details in [HISTORY.md](HISTORY.md) and the linked research docs:

- **Test retry flags / retry tolerance are banned** — retries mask the per-launch race class (a retried VM run green-lit two genuinely broken tests).
- **`run_in_background` strands subagents** — its "re-invokes you" promise is false for them; a subagent that ends its turn mid-work is never resumed. Foreground bounded waits only.
- **Re-asserting `NSApp.mainMenu` is a no-op** — SwiftUI's reconciler mutates the same `NSMenu` instance in place; the shipped fix dropped the SwiftUI lifecycle (`NSApplicationMain`).
- **`hasForegroundJob`-based readiness waits are refuted** — fg==shellPid from ~3 ms; 15–57 ms child bursts invisible to the 150 ms dump sampler; use the computed-marker execution roundtrip.
- **SwiftUI `NSViewRepresentable` hosting renders SwiftTerm black** on macOS 26 — host the terminal view in an AppKit `NSWindow`.
- **The Metal renderer was rejected by measurement** (worse p99 tail, more memory, no median win); resurrecting it requires re-running the archived P7b methodology, not an opinion.
- **The Scope-B project file-tree browser is rejected** as off-mission IDE-creep (P6b addendum in `p6-file-diff-decisions.md`).
- **`launchEnvironment`/CI env vars are stripped by the curated child-env seed wall** — environment fixes must land at the product seam (`ShellResolver`) or they silently no-op.
- **Agent-definition edits reach spawns with unpredictable lag** — verify delivery per run (the `Definition:` stamp); a spawn 63 s post-edit was served the stale copy.
- **Guest bash 3.2 has no bracketed paste** — the VM rig's multi-line-paste red is a benign rig residual, not a product bug.
- **The hosted-runner find-bar wrap is not reproducible from the image build** — stock macOS `PS1='\h:\W \u\$ '` is byte-identical on runner + VM (`runner-images` sets no `PS1`); the runner's ~61-char `\h` is GitHub-network-injected at *runtime* (the image sets only `Mac-<epoch>.local`), so the sole reproduction lever is hostname *length*, which we control — and the short-`\h` Tart VM is blind to prompt-width flakes by construction (`ci-runner-prompt-width-forensics.md`).
- **`xcrun -f metal` inside a VM is a false positive** — it PATH-resolves while the toolchain is unfetchable in-guest.
- **The macOS Local Network gate cannot be granted or neutralized at build time** — not TCC (LN is not a TCC service; the DB has no `kTCCServiceLocalNetwork`), not TN3179's `defaults write Allowed*LocalNetworkAddresses` (a *destination-address* exemption, orthogonal to xtty's reverse-DNS *query* trigger — refuted baked-in too), not an NE-store pre-seed (`nesessionmanager` prunes records lacking live-consent provenance on every boot; only an explicit user *Allow* both persists and silences), not the SSH/CLI-child auto-grant (a GUI app bundle is its own responsible code). The durable fix removes the trigger: `PaneController.localHostNames` from `gethostname()` (matches the shell's `$HOST`, behavior-preserving + more correct) — or run the shell-dependent suite **headless** (`local-network-privacy-forensics.md` §8). **(2026-07-08: the removal-of-trigger fix landed & archived as `fix-osc7-hostname-reverse-dns` — the `gethostname()` swap, measured GREEN by effect: 0/0/0 on a fresh graphics zsh rig; §9.)**
- **Don't pre-build a speculative dev-workflow agent roster** — add an `xtty-*` agent only after its friction recurs across several changes and is provably under-done (both existing agents were reactive; a proposed roster-of-4 was refuted by the dev-workflow forensics → build one **change-set-aware** `openspec-critic` first, adopt fork-per-change authoring as a habit). Delegate only above the ~12k-token subagent-inheritance floor; compute cross-artifact state on demand, never cache counts (`dev-workflow-agent-orchestration.md`).
- **A rule that lives only in AGENTS.md doesn't reach the `/opsx:apply` loop** — the generic apply skill walks `tasks.md` checkboxes, models only *implement* tasks, and never re-reads AGENTS.md; `config.yaml` `rules` don't ride `openspec instructions apply` either. So any *recurring apply-time procedure* must be written at the **point-of-tick** — a marker in the task line (this is why the three delegations **and** the archive ritual all carry a `⟶` marker; measured: the `fix-osc7` archive, with no marker, improvised `openspec archive` and stalled until the user intervened). The archive marker (`⟶ archive-ritual`) must anchor to the **hand-authored committed** procedure in this file, never to the CLI-generated `/openspec-archive-change` skill — even though that skill is now tracked too, `openspec init`/`update` can rewrite it on a version bump, so the hand-authored procedure (whose text is under our control) is the stable anchor a committed task can depend on. Guideline **G13**, `archive-trigger-affordance-forensics.md`.
- **Don't skip-and-partition the shell-dependent XCUITests (per-shell `.xctestplan`s + honest `XCTSkip`) — parameterize-and-assert instead.** A skip is a coverage hole (it verifies nothing on that shell) and the two-`.xctestplan` partition adds machinery + XcodeGen-fidelity risk; since the shell behaviors are *measured*, each shell-dependent test should assert the **correct behavior for the terminal's observed capability** (`bracketedPasteMode` / capture-active), keeping a skip only as a last resort. Settled by `split-shell-dependent-testplan` (the original skip-and-partition sketch was pivoted at explore, then measured **`41/0/1` on both goldens with 0 vacuous passes** and **0 last-resort skips** — the partition was dropped, never introduced). `research/03-analysis/shell-dependent-test-partitioning.md`.
- **A `$0` local `make install` needs no DMG / notarization / Homebrew ceremony — those are download-channel-only.** A locally-compiled app never receives `com.apple.quarantine` (verified 2026-07-08 on xtty's own Debug **and** Release builds), so an ad-hoc (or `xtty-dev`-signed) Release copied to `/Applications` launches clean past Gatekeeper — DMG/notarization/cask matter only for a *downloaded* artifact (the deferred `$99` `add-distribution-signing`/`add-homebrew-distribution`). The install target = build `-configuration Release` → `ditto` to `/Applications`, version stamped via a CLI `MARKETING_VERSION=…` override (proven to reach the synthesized `Info.plist`), plist fields kept numeric (the `git describe --tags --always` draft was refuted — `--always` defeats the `|| echo` floor). Guideline G14; `research/03-analysis/local-install-workflow-research.md`. **(2026-07-08: shipped & archived as `add-install-workflow` — `make install`/`make restart` + the `v0.0.1` tag; measured `Signature=adhoc`, `CFBundleShortVersionString=0.0.1`/`CFBundleVersion=256` numeric, empty `com.apple.quarantine`, install survives `make clean`.)**
- **A raw `CGEvent` HID scroll is silently dropped by the XCUITest runner — drive wheel gestures through XCUITest's automation channel, not `.cghidEventTap`.** The `xttyUITests-Runner` has no Post-Event/Accessibility grant (`CGPreflightPostEventAccess=false`, Codex-rescue-confirmed), so a `CGEvent(scrollWheelEvent2Source:…)` posted to `.cghidEventTap` never lands (and `CGWarpMouseCursorPosition` moves the cursor *sprite* but doesn't update the WindowServer's window-under-cursor, so even a pixel-correct raw scroll misroutes — proven by a coord read-back that matched the target yet routed nowhere). Use `XCUIElement.scroll(byDeltaX:deltaY:)` (element-targeted, cursor-independent) for the gesture and wrap it in `XCUIElement.perform(withKeyModifiers: .shift) { … }` for a Shift-modified wheel — a held-Shift CGEvent keyDown is **not** picked up by the automation-synthesized scroll (flags=0). Sign: XCUITest `scroll` positive `deltaY` = wheel-**up** (button 64); a `CGEvent` `wheel1` sign is the *inverse*. Settled landing `fix-scroll-wheel-mouse-reporting` (`AppUITests/XttyMouseWheelUITests.swift`); peekaboo (an external, granted process) *can* post the raw scroll, which is why the manual verify-by-effect worked where the runner's raw post did not.
- **zsh's line editor (ZLE) turns application-cursor mode (DECCKM/`smkx`) ON at every prompt** — so a bare **zsh** prompt reports SS3 `ESC O A/B` cursor keys while a bare **bash** prompt reports CSI `ESC [ A/B`. A DECCKM-dependent test must **not** assume "normal at a bare prompt" (bash-only). Hold a known DECCKM state deterministically across both goldens by keeping the shell busy in a foreground command (`printf '…'; sleep N`) so ZLE can't re-toggle `smkx`/`rmkx` between the setup and the gesture. Settled by `fix-scroll-wheel-mouse-reporting`'s two DECCKM cursor-key XCUITests (normal + application arms, green on both goldens).
- **Don't drop momentum, cap-and-discard scroll distance, or time-throttle the wheel** — a blanket `momentumPhase` guard stops trackpad/Magic-Mouse scrolling dead the instant fingers lift (no native inertial coast), and a fixed per-gesture emission cap that subtracts the full accumulated delta while emitting only the cap silently discards travel on fast flicks. Bound flood by **whole-cell quantization** instead (accumulate a losslessly-carried sub-cell remainder, emit ~1 report/key per whole cell traversed, reset the remainder on each new gesture's `.began` phase) — the mechanism all 5 surveyed mature peers (iTerm2, Ghostty, kitty, WezTerm, Alacritty) use; none drop momentum or cap-and-discard. Settled by `smooth-scroll-wheel-momentum` (measured by-effect on a physical trackpad: coast continues after finger-lift, no lost distance on a fast flick, htop stays interactive through the coast); `research/03-analysis/scroll-momentum-smoothness-research.md`.

- **A model-authored artifact can never gate archive — the human is the gate, not the model.** The self-policing shape (model writes a "converged" receipt, archive mechanically trusts it) was refuted: a model can dismiss every finding and self-certify by doing its assigned job. Shipped shape: the worker is arbitrarily helpful but carries **zero authority**; eligibility is a **human attestation** (a reviewed-state digest on a delimited `tasks.md` line) checked against git by committed deterministic tooling — confirmed by effect (fails closed on a bare/uncommitted/stale attestation; the model, asked to write its own, correctly refused). `research/03-analysis/cross-model-design-review-axes.md`.
- **Don't harden a mechanical gate against the model that runs it — and don't "iterate cross-model review until both models agree."** A 4-round convergence experiment never converged (the adversary is the model running the tool — it controls git history, so the bypass set is unbounded, reducing to the accepted **R3** residual). Fix: thin the *claim* (mechanical checks are accident tripwires, not guarantees) and validate dev tooling by **building + using it**, not by more adversarial review — which has a hard diminishing-returns cliff (~2–3 useful rounds). `research/03-analysis/cross-model-review-tar-pit-forensics.md`; **G-TARPIT-1..5**.
- **Don't reach for a write-capable drilling reviewer to fix a weak external review — brief the read-only pass instead.** `/xtty:cross-review`'s Codex Pass B shipped blind (no focus text); once briefed, a **read-only** Codex found this project's two biggest gate defects by reading alone — the bottleneck was under-briefing, not the sandbox. Shipped as **A'**: a brief passed as the trailing positional, additive + advisory, staged out-of-repo to survive shell-quoting. `research/03-analysis/codex-review-integration-forensics.md`.
- **A second model earns its cost by RUNNING the other's falsifiers, not by discussing with it — and two-model agreement is NEVER corroboration.** Agreement bounds bloat, not wrongness; a third party must re-derive every load-bearing number from ground truth (both models once shared a false frame neither could see from inside — caught only by non-voting re-measurement). A participating model may never author the synthesis or call it "converged." Point a second model family at the **code**, not the doctrine — that's where independent value concentrates (a code diff produced completely disjoint defect sets). `research/03-analysis/cross-model-pairing-consult-research.md` (**G-CONSULT-1..15**).
- **Past the review cliff the FIXES introduce defects faster than the review removes them.** An 11-round loop: round 10's 5 fixes → round 11 found 11 new findings, ≥4 introduced by those fixes (one blocked the user's own unrelated repos). Once past the cliff, stop patching-and-re-reviewing: freeze the design, build it, let the fixtures adjudicate — the first real execution found 4 defects 11 review rounds had missed. A fixture that never fails is decoration: mutation-test it. `research/03-analysis/cross-model-review-tar-pit-forensics.md` (§13, **G-TARPIT-6/7**).
- **A recovery instruction that satisfies a safety check's own condition is indistinguishable from defeating it** — happened twice in one file, one session (`A-15-7` → `A-C-5c`): telling a user to run a command that makes the NEXT routine command treat their content as "verified ours, safe to overwrite." `research/artifacts/guide-gate/README.md`.
- **There is no executable archive gate today — the four checks are AGENTS.md prose a model is trusted to re-type, and its scope classifier is non-attributive and latches.** Not running step-0 bypasses everything undetected; the classifier's `exit 10`/`exit 0` verdict is a property of the reviewed *range*, never the change — no check may use it as a proxy. The live defect is the `exit 0` waiver arm (an under-inclusion hole); "narrow the range to the change's own paths" is retired (not git-derivable, anti-aligned with the real bypass). **Any replacement MUST dispose of the `exit 0` arm explicitly** (fix the base rule · gate unconditionally · accept the hole in writing), and **check (4) is UNSETTLED — do not re-litigate it in-model** (its prescription flipped 4×; the tension is formally irreducible for a git-only gate). Emission + enforcement remain unfixed — take findings to `/opsx:explore`, adopt no fix from the capture. `research/03-analysis/cross-review-gate-defect-forensics.md` (§9; **G-GATE-1..9**).
- **AGENTS.md's leanness rule was overridden, not unheard — the disease is admission, not reach.** The rule existed at three surfaces (a spec SHALL, a skill instruction, an agent's guard) and was **overridden** every time; 100% of two regrowths to ~80 KB was *instructed* writing, not a rogue append. A guard scoped to one surface only **displaces** growth to an unguarded one — it doesn't stop it. The fix is a mechanical gate below the agent (`make hooks`, *Building*), not another advisory surface. `research/03-analysis/agents-md-structural-best-practices.md`.

## Tech stack (primary: "All-Swift")

- **UI/chrome:** Swift + SwiftUI/AppKit
- **Renderer:** *researched Phase-8 path, skipped by the closed P7b gate — xtty ships SwiftTerm's CoreGraphics renderer.* The sketch: custom Metal view (`MTKView`/`CAMetalLayer`), CoreText glyph atlas, dedicated render thread, **latency-first** (frame pacing > throughput)
- **VT engine:** reuse **SwiftTerm**'s headless `Terminal` core (parser + grid)
- **PTY:** Darwin `posix_openpt`/`forkpty` + kqueue read/write loop
- **Shell integration:** OSC 7 (cwd) + OSC 133 (command boundaries) capture

Researched alternatives if we hit limits (Rust core + Swift, Zig/libghostty + Swift, Swift + libghostty-vt) are in `research/04-design/01-stack-sketch.md` with switch triggers.

## Building

The Xcode project is generated from a committed `project.yml` via **XcodeGen**; the resulting `xtty.xcodeproj` is **gitignored** (never commit it).

**Quick start — use the `Makefile`.** It is the single entry point; run `make` (no target) — it self-documents every target with a one-line description (that live list is the source of truth, not a table here). Non-obvious behavior worth calling out: `make test`'s benchmark e2e is opt-in (`XTTY_RUN_BENCH_E2E=1`, so routine runs never prompt for Screen Recording); `make bench`'s latency figure is **coarse/experimental** while memory is the trustworthy result (`research/03-analysis/p7-measurement-methodology.md`); `make image`'s prereqs are human-gated, never auto-installed (packer + a one-time Apple-ID Xcode `.xip`; see `packer/README.md`); `make install`'s options are self-documented in the `Makefile` (rationale: `research/03-analysis/local-install-workflow-research.md`).

The targets are thin wrappers — reach for the underlying commands below directly if you're not using `make`, or to understand what a target does:

- **Prerequisite:** XcodeGen — `brew install xcodegen` (developed against **v2.45.4**). Building/testing the app target needs **full Xcode** (the Command Line Tools alone lack `xcodebuild`, `XCTest`, and swift-testing). Verified against **Xcode 26.6**.
- **SwiftTerm checkout (one-time):** a **gitignored upstream clone** at `external/SwiftTerm`, reconstituted from a pinned ref with a tracked patch applied by `scripts/bootstrap-swiftterm.sh` (run once after cloning; the `make` build targets auto-run it). **Never edit the clone directly** — bootstrap restores it pristine every run; change the tracked patch instead. Mechanism + rationale: `research/03-analysis/swiftterm-fork-vs-patch-strategy.md`.
- **Local VM test image (optional):** `make image` builds the Tart image for CI-parity XCUITest runs (the per-launch race class reproduces at 3 vCPU in a VM, not on bare metal). Prereqs, runtime workflow, acceptance envelope, expected-difference matrix: **`packer/README.md`**.
- **Generate the project:** `xcodegen generate` (re-run after editing `project.yml` or adding/removing source files).
- **Build & run:** open `xtty.xcodeproj` in Xcode, or `xcodebuild -project xtty.xcodeproj -scheme xtty build`.
- **Core package:** `XttyCore` is a local SPM package (the engine-facing seam). It builds/tests standalone from `XttyCore/` via `swift build` / `swift test` (tests need Xcode's toolchain for XCTest).
- **Install a stable build:** `make install` (Release build → self-contained copy in `/Applications`, survives `make clean`); `make restart` relaunches. **$0 — no notarization, no Apple account** (a locally-compiled app is never quarantined). Options are `Makefile`-self-documented; rationale: `research/03-analysis/local-install-workflow-research.md`.
- **Guide gate (`make hooks`):** a tracked git pre-push hook, armed via an order-only prerequisite of the routine `build`/`test`/`test-core`/`run`/`install`/`setup` targets, refuses a push that grows the eagerly-injected `AGENTS.md`/`CLAUDE.md` guide past a measured, ratcheting ceiling (a shrink or unchanged push always passes; the ceiling only ever lowers). A refused append is **parked**, never dropped — see *How to work here* below. Mechanism + fixture/mutant proof: `research/artifacts/guide-gate/README.md`; the diet/ratchet history: `research/03-analysis/agents-md-structural-best-practices.md`; `make test-guide-gate` re-runs the fixtures + mutants locally.

Signing posture (P0): **App Sandbox OFF** (`App/xtty.entitlements`), **Sign to Run Locally** (ad-hoc identity), Hardened Runtime/notarization deferred.

- **Optional stable local signing:** the ad-hoc identity changes every rebuild (TCC re-prompts) — run `scripts/create-signing-cert.sh` once, then build with `XTTY_SIGN_IDENTITY=xtty-dev`. Distribution signing is researched green but gated on the ~$99/yr program: `research/03-analysis/distribution-signing-research.md`.

### Continuous integration (GitHub Actions)

CI runs on every push and pull request via `.github/workflows/` — **$0 and secret-free** (the ad-hoc default needs no Apple credentials; standard `macos-26` runners are free + unlimited on public repos). Three jobs in `ci.yml`:

- **`test-core`** (the **required gate**) — reconstitutes SwiftTerm and runs the fast view-free `XttyCore` unit tests (`swift test`, no app build). Deterministic; this is the check to require in branch protection.
- **`build-and-test`** (**non-blocking**) — `xcodegen generate` + `xcodebuild test` (the app XCUITests), retry-tolerant, uploads the `.xcresult` on failure. Kept out of required checks while hosted-runner XCUITest reliability is being proven.
- **`guide-gate`** (**non-blocking**) — verifies `make hooks` reproduces the tracked pre-push hook byte-identically, then runs the guide-gate fixture suite + mutation matrix. An installer regression test over CI's own clone, **not** a detector of unarmed developer clones (`research/03-analysis/github-actions-ci-cd.md` §20).

`test-core` and `build-and-test` cache the reconstituted `external/SwiftTerm` (keyed on the pin + patch); no Metal-toolchain guard is needed — the build is Metal-free (`retire-metal-renderer`); `guide-gate` needs neither Xcode nor SwiftTerm. `pr-lint.yml` enforces Conventional Commit **PR titles** (pull requests only). The workflows call `scripts/bootstrap-swiftterm.sh` directly (not `make`). Release/notarization are **not** in CI (deferred). Current CI truth: `test-core` is green and gate-worthy; `build-and-test` is non-blocking with the menu-clobber fix confirmed on CI and 2 residual rig fragilities (find-bar marker-wrap on the runner's ~72-char prompt; multi-line paste on bash-3.2) deferred to a harness-truthing successor. Full investigation record + expected-difference matrix: `research/03-analysis/github-actions-ci-cd.md`.

## Product values (hard requirements)

- **Lean memory** — nowhere near Warp; bound scrollback, manage the glyph atlas, avoid retain cycles.
- **No account / no login, free and open, no paywalled features.**
- **Native macOS feel**; keep the user's existing zsh/tmux/dotfiles working.
- **Great host for agent CLIs** (Claude Code, etc.) — agents pluggable/local, not vendor-locked.

Signature features: at-a-glance per-session progress sidebar (from OSC 133); a *lightweight* in-terminal file/diff view (not a full IDE). Full list: `research/03-analysis/xtty-requirements.md`.

## How to work here

- **Implementation follows the phased plan** in `research/04-design/02-milestones.md` (P0 skeleton → P5 daily-driver → **P7 OSC capture (keystone)** → P8 sidebar → P10 polish). P8/P9 depend on P7.
- **Use OpenSpec for non-trivial changes** (see the OpenSpec workflow section below). The project `context` in `openspec/config.yaml` is shown to the AI on every artifact.
- **Research is background, not spec.** `research/` records *why*; `openspec/specs/` will record *what is true*. When they conflict once code exists, specs win.
- **Write up research in `research/` when it's done.** Whenever an investigation or spike produces durable findings — a tooling landscape, a comparison, an internals discovery, a dead end worth remembering — capture it as a `research/` doc *as soon as it settles* (even mid-build), in the right subfolder (`03-analysis/` for analysis, `02-internals/` for internals, `04-design/` for build-plan shifts). Follow the research-doc conventions (Provenance + Sources + ✅/❌/❓) and add it to `research/README.md`. **Capture depth — settle the *mechanism*, not just the conclusion (scaled to the finding).** Any capture with **measured claims or retired theories** carries: (1) the **mechanism/internals** (how the system actually works, with the evidence); (2) **reproducible probes** — the exact commands, what each proves *and cannot prove*, including instruments that did **not** work; (3) the **investigation record** — each retired theory as a ❌ *next to the experiment that killed it* (a fates table), so stale claims can't be cited and theories don't respawn; (4) **re-verify by effect** — how a future reader re-checks the headline claim (never a syntax/read-back check); (5) when the finding generalizes, a distilled **reusable guideline** (numbered); (6) pointers to the **evidence artifacts**. Lightweight captures (a landscape/comparison with no measurements) skip these. Exemplar: `research/03-analysis/local-network-privacy-forensics.md`. Keep the *why/landscape* in `research/`; the actionable *decision* belongs in the OpenSpec change.
- **Keep progress current when implementation lands — and keep it lean.** When a change (or a milestone's tasks) is done, update the trackers in the same session: tick the `tasks.md` checkboxes; update the change's **row in the Current-status table** (bounded: state + one-liner + detail pointer — **never a narrative paragraph**); refresh the **snapshot block** if counts/envelope/milestone position moved; **append the full narrative to [HISTORY.md](HISTORY.md)** under a dated heading in the matching section; and advance the milestone state in `research/04-design/02-milestones.md`. If the change settled a refutation worth never re-litigating, add a one-liner (with its conclusion) to the **Learned refutations** list. **Then verify against disk** — `openspec list` (active changes must match the open-changes table), `ls openspec/changes/archive/` (archived changes must be marked archived, not "pending archive"), `ls openspec/specs/` (the guide carries no cached list — disk is the truth) — and fix any tracker that disagrees with reality. Don't leave finished work looking pending or stale. The **`/xtty:capture-research`** command + **`xtty-capture-research`** skill walk this whole capture-and-reconcile checklist (place + index the research doc → reconcile the trackers → verify-against-disk). **The standard change tail — drive completion from a point-of-tick marker.** Archive + reconcile is the one recurring apply-loop procedure that lives only in this file, so it drifts out of reach of the generic `/opsx:apply` loop (measured on the `fix-osc7-hostname-reverse-dns` archive: the completion task folded archive into an implicit "on completion" clause with no procedure pointer, so the loop improvised `openspec archive` and never reached the archive skill the user expected). Give every change the same recognizable tail so the ritual reaches the checkbox-walker: (1) a **pre-archive coherence** task marked `⟶ xtty-openspec-critic (<change>)`, then (2) an **archive + reconcile** task carrying `⟶ archive-ritual`. `⟶ archive-ritual` resolves to the **committed hand-authored** procedure — the OpenSpec workflow's *"After archiving, finish the merge by hand"* + this *Keep progress current* rule + the `openspec archive` CLI — **not** to the openspec-generated `/openspec-archive-change` skill (that skill is now tracked too, but it is CLI-generated — `openspec init`/`update` can rewrite it on a version bump — so it stays an **optional accelerator**, never the stable anchor a committed task depends on). Unlike the three delegation markers, `⟶ archive-ritual` is a **procedure pointer, not an agent delegation** — the ritual runs inline and produces the very tracker edits the session must own, so there is nothing to delegate and `xtty-openspec-critic` does **not** expect an agent for it. **Pre-tick self-check:** before ticking the archive task, confirm the spec deltas merged into `openspec/specs/`, the trackers reconciled (row + snapshot + HISTORY + milestone + refutations), and verify-against-disk ran.
- **A refused guide append is parked, never lost.** The guide gate (`make hooks` → *Building*) refuses a push that grows the eagerly-injected guide past its ratchet ceiling; on refusal, route the finding to its named, tracked, lazily-loaded destination ([HISTORY.md](HISTORY.md) for narrative, a `research/` capture for findings) and keep only a bounded pointer in the guide. **Never relocate refused content to another eagerly-loaded surface** (an unscoped `.claude/rules/` file, `CLAUDE.local.md`, etc.) — the gate's meter covers those too, so that would refuse again, not escape it.
- **Committed agents/launchers are delegated recurring work, not run inline.** Each of the four below floods the main session with noise (build/VM logs, CI attachments, rule-checking greps, source clones) if run directly, so it's a committed, version-controlled agent or launcher instead. All four share the same shape: **two spawn scenarios** — (a) a direct user request via the launcher command or plain natural language, (b) delegation from an OpenSpec `tasks.md` task — and **one delegation boundary verb pair** — a cheap/iterate verb stays inline, an expensive/validate-accept verb is delegated. A delegate-set task in any `tasks.md` MUST carry the row's marker in the task line itself (`/opsx:apply` reads the marker at the point-of-tick, not this rule — a rule that lives only here never reaches the checkbox-walking loop).

## OpenSpec workflow

We do **spec-driven development**: formalize *what* changes as reviewable artifacts, approve, then implement. Don't write feature code straight from a chat prompt — capture it as a change first.

**The loop** (one change per milestone from `research/04-design/02-milestones.md`):

```
explore ──▶ propose ──▶ apply ──▶ archive
(think)    (artifacts) (implement) (merge into specs/)
```

**Slash commands** (preferred entry points):
- `/opsx:explore <topic>` — thinking/investigation mode. **Never implements**; may read code/clone OSS to `/tmp` for understanding and may create OpenSpec artifacts. Use it before committing to an approach.
- `/opsx:propose <name>` — create a change and generate all artifacts (`proposal.md` → `design.md` + `specs/` → `tasks.md`).
- `/opsx:apply` — implement a proposed change by walking its `tasks.md` checkboxes. This is where real code gets written.

**Underlying CLI** (`openspec`, v1.4.x):
- `openspec list` — active changes · `openspec list --specs` — established specs
- `openspec new change "<name>"` — scaffold a change
- `openspec status --change "<name>" [--json]` — artifact build order & paths
- `openspec instructions <artifact> --change "<name>" --json` — template + rules for an artifact (follow these; do NOT copy the `context`/`rules` blocks into the file)
- `openspec validate "<name>"` — validate before committing
- `openspec archive "<name>"` — on completion, merge spec deltas into `openspec/specs/`

**Artifact order & dependencies:** `proposal` → (`design` + `specs`) → `tasks`. `tasks` is the apply gate.

**Spec delta format** (in `changes/<name>/specs/<capability>/spec.md`):
- Use `## ADDED Requirements` / `## MODIFIED Requirements` / `## REMOVED Requirements`.
- `### Requirement: <name>` with **SHALL/MUST** (avoid should/may); every requirement needs ≥1 scenario.
- `#### Scenario: <name>` with **WHEN/THEN** — scenarios MUST use exactly **4 hashtags** (3 fails silently).
- A **MODIFIED** requirement MUST paste the **entire** existing block from `openspec/specs/<capability>/spec.md`, not a fragment — partial content silently loses detail at archive.

**Keeping a change coherent.** The four artifacts are a dependency chain (`proposal → design + specs → tasks`), so a requirement edit rarely lives alone. When you add/modify/remove a requirement in `changes/<name>/specs/`, walk the full per-artifact checklist in `research/03-analysis/openspec-coherence-checklist.md`, then run `openspec validate "<name>"` (it catches missing deltas/scenarios). The two costliest-to-miss gotchas are already stated above: scenarios need exactly 4 hashtags, and a MODIFIED requirement must paste the entire existing block.

**Lifecycle rule:** `openspec/specs/` is the source of truth and only grows via `openspec archive` after a change is implemented. In-flight work lives in `openspec/changes/<name>/`. Commit proposal artifacts as `docs(openspec): …`; commit the implementation under the relevant `feat`/`chore` scope.

**Before archiving an in-scope change, run the cross-model gate's step-0 fail-closed precondition first** (see *Cross-model design review + the human-attestation archive gate* below) — it is the first act of the `⟶ archive-ritual` for any change the mechanical scope classifier deems in scope, and it gates the `openspec archive` that follows.

**After archiving, finish the merge by hand:** `openspec archive` merges spec deltas mechanically, so check the result before committing — (1) fill in the `## Purpose` of any **newly-created** spec (archive stubs it with `TBD - … Update Purpose after archive.`); (2) make the merged requirement text reflect *what actually shipped*, not what the proposal guessed (specs record what is true — e.g. correct the delta if the implementation diverged); (3) `openspec validate --all --type spec` and skim the diff for collapsed blank lines. Then commit as `docs(openspec): archive …`.

### Cross-model design review + the human-attestation archive gate

For a change **in scope** (by the mechanical classifier), a single-model coherence pass is insufficient — pair it with a **cross-model soundness** review and a **human gate** on archive. One hard rule between the layers: **the worker is arbitrarily helpful but carries ZERO authority; the gate is authority-complete, has near-zero machinery, and reads NO model-authored artifact.**

- **Scope classifier (never a model judgment):** `scripts/cross-review-scope.sh <change>` classifies **every path in the reviewed range** against a **fixed allowlist** of docs/tracker surfaces — any path **outside** ⇒ in scope (exit 10); an **unrecognized/ambiguous path ⇒ in scope, fail-closed**; all inside ⇒ out of scope (exit 0); an unresolvable range ⇒ refuse (exit 2). ⚠️ **It scopes the RANGE, not the change: the verdict is non-attributive and it LATCHES** (see Learned refutations — no check may use it as a proxy for a property of the change).
- **The worker** — `/xtty:cross-review <change>`, a **main-loop protocol**, human-launched only, **never auto-fires**; **one launch authorizes the whole bounded run** (the spend rule). Three passes: **A** Opus critic (conformance) · **B** Codex `gpt-5.6-sol` soundness, backgrounded via Bash `run_in_background`, **never a subagent** (strand refutation) · **C** an **inline** Fable 5 soundness pass — an in-vendor Claude checkpoint diversity slice sharing Pass A's family (not a third independent family; Pass B remains the review's only cross-vendor diversity), its comparative value against Pass A judged only by a human reading the ledger across runs, never model-computed. Both B and C are **BRIEFED** (design intent + claims-to-check + drill digest, passed as the trailing positional, staged out-of-repo via `mktemp` → `"$(cat)"`): **additive** ("check these **and** anything outside them") and **advisory**. It merges into **one union ledger** whose **header records the reviewed base + HEAD + the file list + the effective model of each pass**, flags **heuristic two-model consensus**, iterates a **bounded N=2** fix→re-review loop, and **surfaces the complete ledger on every run**. **Detectable non-gating degradation:** an unavailable reviewer (no companion, `codex` absent, logged out) ⇒ **skip Pass B, complete on A + C, and say so in the header (single-model)** — it never silently degrades. **Every worker output is advisory** — no verdict, coverage label, or consensus flag carries gate force; *"converged" has no gate force; there is no receipt.*
- **The gate is a HUMAN ATTESTATION.** The human runs the review, **reads the complete ledger**, runs `scripts/cross-review-digest.sh <change>`, and ticks the task recording a delimited line in `tasks.md`:
  `<!-- cross-review-attestation: base=<B> head=<HEAD> digest=<sha256> reviewed=<date> -->`
  **HUMAN-ONLY — the model MUST STOP:** it may not tick the task and may not derive the attested value.
- **Archive step-0** (the first act of `⟶ archive-ritual`, before `openspec archive`) refuses unless all four hold: the line **exists and is well-formed** · the digest **recomputes and string-equals** it · the tree is **clean** · **exempt-by-act** (the line is added exactly once and never modified, `adds==1 && dels==0`). Run the scripts **from the reviewed-base version** (that anchor is what stops a checker edit from self-validating). ⚠️ **The bootstrap boundary:** only a tooling-*introducing* change has no prior version, and the anchor there is **human code review of the committed scripts** — stated, not mechanically closed. An **optional strong form** (a signed attestation, verified when present) exists but is **NOT the default**. ⚠️ These four are **accident tripwires and human-legibility aids, NOT adversarial guarantees** — adversarial resistance rests on **the human reading the ledger**, plus the accepted repo-controlling-model residual (R3).

**Two axes:** the critic checks **conformance**; the cross-model passes check **soundness**. Complementary, not redundant.

⚠️ **The gate has known, unfixed defects — read the Learned-refutations entry before touching it.** Mechanisms + the full 6-round derivation: `research/03-analysis/cross-model-design-review-axes.md`, `cross-model-review-tar-pit-forensics.md`, `cross-review-gate-defect-forensics.md`, `codex-review-integration-forensics.md`. The protocol itself: `.claude/commands/xtty/cross-review.md`; what is true: `openspec/specs/cross-model-review/spec.md`.

## Conventions

- **Commits: [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/)** — `type(scope): description`. Types used so far: `docs` (research/design/openspec content), `feat`/`test` (implementation), `chore` (tooling). Scopes: `research`, `design`, `openspec`, `app`. End commit messages with the `Co-Authored-By` trailer when authored with an AI.
- **Research docs** carry a **Provenance** note (date + how produced) and a **Sources** list; fact-checked claims use ✅/❌/❓. Snapshots are dated and time-sensitive — re-verify versions/latency/pricing before quoting.
- **Engineering bias:** macOS-first; **reuse battle-tested components over hand-rolling** (especially the VT parser — use the Williams state machine via a library); favor **latency and low memory** in every tradeoff.
- **Don't track local tooling — except the version-controlled workflow tooling:** `.claude/` is gitignored **except** two committed sets. (1) This project's own **hand-authored** tooling — `.claude/commands/xtty/` + `.claude/skills/xtty-*/` + `.claude/agents/xtty-*` (the `/xtty:capture-research` command + the `xtty-capture-research` skill + the `xtty-test-validator` agent + its `/xtty:validate` launcher command + the `xtty-ci-investigator` agent + its `/xtty:investigate-ci` launcher command + the `xtty-openspec-critic` agent + its `/xtty:review` launcher command + the `/xtty:research` source-research launcher command — worker is a Workflow, no standing agent — + the `/xtty:cross-review` cross-model-review launcher command, a **main-loop protocol** (not a delegated agent — it drives a detached reviewer + edits artifacts between rounds, which a subagent would strand) whose Pass C soundness reviewer runs **inline**, not as a standing agent, per the anti-roster refutation). Its two committed deterministic gate scripts — `scripts/cross-review-digest.sh` (reviewed-state digest) and `scripts/cross-review-scope.sh` (mechanical scope classifier) — live under `scripts/` (always tracked, outside the `.claude/` exception). (2) The **openspec-generated** workflow tooling — `.claude/commands/opsx/` + `.claude/skills/openspec-*/` — tracked but **pinned to a recorded CLI version** (the `generatedBy` stamp each file carries), so a fresh clone has the `/opsx:*` workflow present and its prompt text can't drift under a silent CLI bump: regenerate it *only* via the explicit `openspec init`/`update` step and **re-commit the diff deliberately** on a version bump (routine `openspec list`/`validate`/`status` are proven to leave the files byte-identical, so day-to-day work produces no spurious diffs). Only machine-local Claude files — `settings.local.json` and runtime locks — stay ignored.
