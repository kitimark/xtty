# AGENTS.md — xtty

Guidance for AI agents (and humans) working in this repository. This is the canonical project guide; `CLAUDE.md` symlinks to it.

## What this project is

**xtty** is a **native macOS terminal emulator**. It is greenfield and in the **build** phase: the app already launches a live terminal (the user's login shell in a SwiftTerm engine hosted in AppKit). The direction, requirements, and design are documented in `research/`; implementation proceeds milestone-by-milestone via the OpenSpec workflow.

**Learned refutations — do not re-propose.** Each was settled by measurement; details in [HISTORY.md](HISTORY.md) and the linked research docs:

- **Test retry flags / retry tolerance are banned** — retries mask the per-launch race class (a retried VM run green-lit two genuinely broken tests).
- **`run_in_background` strands subagents** — its "re-invokes you" promise is false for them; a subagent that ends its turn mid-work is never resumed. Foreground bounded waits only.
- **Re-asserting `NSApp.mainMenu` is a no-op** — SwiftUI's reconciler mutates the same `NSMenu` instance in place; the shipped fix dropped the SwiftUI lifecycle (`NSApplicationMain`).
- **`hasForegroundJob`-based readiness waits are refuted** — fg==shellPid from ~3 ms; 15–57 ms child bursts invisible to the 150 ms dump sampler; use the computed-marker execution roundtrip.
- **SwiftUI `NSViewRepresentable` hosting renders SwiftTerm black** on macOS 26 — host the terminal view in an AppKit `NSWindow`.
- **The Metal renderer was rejected by measurement** (worse p99 tail, more memory, no median win); resurrecting it requires re-running the archived P7b methodology, not an opinion.
- **The Scope-B project file-tree browser is rejected** as off-mission IDE-creep (P6b addendum in `p6-file-diff-decisions.md`).
- **A parser cap cannot bound memory after full producer materialization, and `--no-ext-diff --no-textconv` does not contain submodule recursion** — bound stdout while streaming (including the current physical record), terminate/reap at cutoff, and force `--submodule=short`; `known-product-issues.md` §2.
- **`launchEnvironment`/CI env vars are stripped by the curated child-env seed wall** — environment fixes must land at the product seam (`ShellResolver`) or they silently no-op. `github-actions-ci-cd.md` §11.
- **Agent-definition edits reach spawns with unpredictable lag** — verify delivery per run (the `Definition:` stamp); a spawn 63 s post-edit was served the stale copy.
- **Guest bash 3.2 has no bracketed paste** — the VM rig's multi-line-paste red is a benign rig residual, not a product bug.
- **The hosted-runner find-bar wrap is not reproducible from the image build** — the runner's long `\h` hostname is GitHub-network-injected at *runtime* (stock `PS1` is byte-identical everywhere; the image sets only a short hostname), so the sole reproduction lever is hostname *length* (which we control) — and the short-`\h` Tart VM is blind to prompt-width flakes by construction. `ci-runner-prompt-width-forensics.md`.
- **`xcrun -f metal` inside a VM is a false positive** — it PATH-resolves while the toolchain is unfetchable in-guest.
- **The macOS Local Network gate cannot be granted or neutralized at build time** — all four routes measured dead: TCC seeding (LN is not a TCC service), TN3179's `defaults write Allowed*LocalNetworkAddresses` (a *destination-address* exemption, orthogonal to the reverse-DNS *query* trigger), an NE-store pre-seed (pruned at every boot absent live-consent provenance), and the SSH/CLI-child auto-grant (a GUI bundle is its own responsible code). Shipped resolution: remove the trigger — the `gethostname()` swap (`fix-osc7-hostname-reverse-dns`, measured 0/0/0) — or run the shell-dependent suite **headless**. `local-network-privacy-forensics.md` §8–9.
- **Don't pre-build a speculative dev-workflow agent roster** — add an `xtty-*` agent only after its friction recurs across several changes and is provably under-done; delegate only above the ~12k-token subagent-inheritance floor, and compute cross-artifact state on demand, never cache counts. `dev-workflow-agent-orchestration.md`.
- **A rule that lives only in AGENTS.md doesn't reach the `/opsx:apply` loop** — any recurring apply-time procedure must be written at the **point-of-tick** as a `⟶` marker in the task line, and the archive marker must anchor to the hand-authored committed procedure in this file, never to the CLI-generated (version-bump-rewritable) archive skill. Guideline **G13**, `archive-trigger-affordance-forensics.md`.
- **Don't skip-and-partition the shell-dependent XCUITests — parameterize-and-assert instead**: a skip is a coverage hole and the per-shell `.xctestplan` partition adds machinery + XcodeGen-fidelity risk; assert the correct behavior for the terminal's *observed capability*, keeping a skip only as a last resort. Settled by `split-shell-dependent-testplan` (0 vacuous passes, 0 last-resort skips); `research/03-analysis/shell-dependent-test-partitioning.md`.
- **A `$0` local `make install` needs no DMG / notarization / Homebrew ceremony — those are download-channel-only.** A locally-compiled app never receives `com.apple.quarantine`, so an ad-hoc (or `xtty-dev`-signed) Release copied to `/Applications` launches clean past Gatekeeper. Shipped as `add-install-workflow` (`make install`/`make restart`). Guideline G14; `research/03-analysis/local-install-workflow-research.md`.
- **A raw `CGEvent` HID scroll is silently dropped by the XCUITest runner — drive wheel gestures through XCUITest's automation channel, not `.cghidEventTap`** (the runner has no post-event grant, and warping the cursor doesn't move the WindowServer's window-under-cursor, so even a pixel-correct raw scroll misroutes). Use `XCUIElement.scroll(byDeltaX:deltaY:)`, wrapped in `perform(withKeyModifiers:)` for a modified wheel. Sign: XCUITest `scroll` positive `deltaY` = wheel-**up**; a `CGEvent` `wheel1` sign is the *inverse*. Settled by `fix-scroll-wheel-mouse-reporting` (`AppUITests/XttyMouseWheelUITests.swift`).
- **zsh's line editor (ZLE) turns application-cursor mode (DECCKM/`smkx`) ON at every prompt** — a bare zsh prompt is application-cursor (SS3) where bare bash is normal (CSI), so a DECCKM-dependent test must **not** assume "normal at a bare prompt"; hold a known state across both goldens by keeping the shell busy in a foreground command. Settled by `fix-scroll-wheel-mouse-reporting`'s DECCKM XCUITests.
- **Don't drop momentum, cap-and-discard scroll distance, or time-throttle the wheel** — a blanket `momentumPhase` guard kills the inertial coast at finger-lift, and a fixed cap that subtracts the full accumulated delta silently discards travel on fast flicks; bound flood by **whole-cell quantization** (a losslessly-carried sub-cell remainder, reset on each new gesture's `.began`) — the mechanism all 5 surveyed mature peers use. Settled by `smooth-scroll-wheel-momentum`; `research/03-analysis/scroll-momentum-smoothness-research.md`.

- **A model-authored artifact can never gate archive — the human is the gate, not the model.** A model can dismiss every finding and self-certify by doing its assigned job correctly; the human-attestation gate built on this refutation was itself retired in full (`remove-cross-model-review`, an owner cost call) — the refutation survives the retirement, and nothing model-authored may replace the human in any future soundness gate. [HISTORY.md](HISTORY.md); `cross-model-design-review-axes.md` (historical).
- **Retiring a mechanical gate does not retire the measured finding that motivated it — record both directions.** `remove-guide-gate` deleted the guide-leanness gate as an owner cost call, but the refutation it was built on stays true: advisory-only guide-leanness was measured insufficient (the regrowths were *instructed* writing, and a guard scoped to one surface only displaces growth) — so don't re-propose a mechanical guide gate without new evidence, and don't treat the advisory `research-capture` convention as proven sufficient either. [HISTORY.md](HISTORY.md); `agents-md-structural-best-practices.md` (historical).
- **A second model earns its cost by RUNNING the other's falsifiers against ground truth — never by discussing until agreement.** Iterate-until-both-models-agree is refuted (a convergence experiment never converged; adversarial review of a repo-controlling model hits a hard diminishing-returns cliff at ~2–3 rounds); **two-model agreement is NEVER corroboration** (agreement bounds bloat, not wrongness — both models once shared a false frame caught only by non-voting re-measurement from ground truth); and **past the cliff the fixes introduce defects faster than the review removes them** — freeze the design, build it, let fixtures adjudicate (mutation-test a fixture that never fails). Point the second model family at the **code**, briefed, read-only — under-briefing, not the sandbox, was the measured bottleneck. `cross-model-review-tar-pit-forensics.md`, `cross-model-pairing-consult-research.md`, `codex-review-integration-forensics.md` (all historical; **G-TARPIT-1..7**, **G-CONSULT-1..15**).
- **Three gate-design defect shapes are recorded so a future gate doesn't reintroduce them:** (1) the retired archive gate's checks were prose a model was trusted to re-type (never executable), and its scope classifier's verdict was a property of the reviewed *range*, not the change — its `exit 0` waiver arm (an under-inclusion hole) was never fixed, only retired with the gate; (2) a reviewed-state digest scoped repo-wide is fragile to ANY commit anywhere before archive, not just the change's own; (3) a recovery instruction that satisfies a safety check's own trust condition defeats the check on the next routine action — never tell a user to mark hand-edited content as installer-owned or otherwise “verified ours”. `cross-review-gate-defect-forensics.md` (§9, **G-GATE-1..9**), `cross-model-seat-assignment-research.md`, [HISTORY.md](HISTORY.md) → `bound-the-agents-md-guide` (all historical).
- **Non-Claude agent CLIs silently truncate AGENTS.md** — Codex (`codex exec`) drops everything past a documented 32,768 B default (override: `-c project_doc_max_bytes=…`) and Antigravity (`agy`) past a measured ~23.5–24 KB band (and ingests nothing at all without an explicit `--new-project`/`--project` registration) — so never assume a rule in the guide's tail reaches them; re-check `wc -c` against both ceilings after any guide edit. `research/03-analysis/agent-guide-ingestion-forensics.md`.
- **Don't delete or pointerize the guide's inline refutation conclusions to save bytes — compress them to bounded one-liners**: deletion regressed the trap probes at both granularities (whole list: T1 0/2; cross-model cluster: G1 0/2, with other traps "passing" only off secondary doc homes — which certifies nothing about the loaded surface), while compression held every trap at parity (S′ 62/66 ≥ N 56/66). `research/03-analysis/agents-md-context-budget.md` (Addendum B).

## Tech stack (primary: "All-Swift")

- **UI/chrome:** Swift + SwiftUI/AppKit
- **Renderer:** *researched Phase-8 path, skipped by the closed P7b gate — xtty ships SwiftTerm's CoreGraphics renderer.* The sketch: custom Metal view (`MTKView`/`CAMetalLayer`), CoreText glyph atlas, dedicated render thread, **latency-first** (frame pacing > throughput)
- **VT engine:** reuse **SwiftTerm**'s headless `Terminal` core (parser + grid)
- **PTY:** Darwin `posix_openpt`/`forkpty` + kqueue read/write loop
- **Shell integration:** OSC 7 (cwd) + OSC 133 (command boundaries) capture

Researched alternatives if we hit limits (Rust core + Swift, Zig/libghostty + Swift, Swift + libghostty-vt) are in `research/04-design/01-stack-sketch.md` with switch triggers.

## Building

The Xcode project is generated from a committed `project.yml` via **XcodeGen**; the resulting `xtty.xcodeproj` is **gitignored** (never commit it).

**Quick start — use the `Makefile`.** It is the single entry point; run `make` (no target) — it self-documents every target with a one-line description (that live list is the source of truth, not a table here). Non-obvious behavior worth calling out: `make test`'s benchmark e2e is opt-in (`XTTY_RUN_BENCH_E2E=1`, so routine runs never prompt for Screen Recording); `make bench`'s latency figure is **coarse/experimental** while memory is the trustworthy result (`research/03-analysis/p7-measurement-methodology.md`); `make image`'s prereqs are human-gated, never auto-installed (packer + a one-time Apple-ID Xcode `.xip`; see `packer/README.md`); `make install`'s options are self-documented in the `Makefile` (rationale: `research/03-analysis/local-install-workflow-research.md`).

The targets are thin wrappers — reach for the underlying commands below directly if you're not using `make`, or to understand what a target does:

- **Prerequisite:** XcodeGen — `brew install xcodegen` (developed against **v2.45.4**). Building/testing the app target needs **full Xcode** (the Command Line Tools alone lack `xcodebuild`, `XCTest`, and swift-testing). Verified against **Xcode 26.6**.
- **SwiftTerm checkout (one-time):** a **gitignored upstream clone** at `external/SwiftTerm`, reconstituted from a pinned ref with a tracked patch applied by `scripts/bootstrap-swiftterm.sh` (run once after cloning; the `make` build targets auto-run it). **Never edit the clone directly** — bootstrap restores it pristine every run; change the tracked patch instead. Mechanism + rationale: `research/03-analysis/swiftterm-fork-vs-patch-strategy.md`.
- **Local VM test image (optional):** `make image` builds the Tart image for CI-parity XCUITest runs (the per-launch race class reproduces at 3 vCPU in a VM, not on bare metal). Prereqs, runtime workflow, acceptance envelope, expected-difference matrix: **`packer/README.md`**.
- **Generate the project:** `xcodegen generate` (re-run after editing `project.yml` or adding/removing source files).
- **Build & run:** open `xtty.xcodeproj` in Xcode, or `xcodebuild -project xtty.xcodeproj -scheme xtty build`.
- **Core package:** `XttyCore` is a local SPM package (the engine-facing seam). It builds/tests standalone from `XttyCore/` via `swift build` / `swift test` (tests need Xcode's toolchain for XCTest).
- **Install a stable build:** `make install` (Release build → self-contained copy in `/Applications`, survives `make clean`); `make restart` relaunches. **$0 — no notarization, no Apple account** (a locally-compiled app is never quarantined). Options are `Makefile`-self-documented; rationale: `research/03-analysis/local-install-workflow-research.md`.
Signing posture (P0): **App Sandbox OFF** (`App/xtty.entitlements`), **Sign to Run Locally** (ad-hoc identity), Hardened Runtime/notarization deferred.

- **Optional stable local signing:** the ad-hoc identity changes every rebuild (TCC re-prompts) — run `scripts/create-signing-cert.sh` once, then build with `XTTY_SIGN_IDENTITY=xtty-dev`. Distribution signing is researched green but gated on the ~$99/yr program: `research/03-analysis/distribution-signing-research.md`.

### Continuous integration (GitHub Actions)

CI runs on every push and pull request via `.github/workflows/` — **$0 and secret-free** (the ad-hoc default needs no Apple credentials; standard `macos-26` runners are free + unlimited on public repos). Two jobs in `ci.yml`:

- **`test-core`** (the **required gate**) — reconstitutes SwiftTerm and runs the fast view-free `XttyCore` unit tests (`swift test`, no app build). Deterministic; this is the check to require in branch protection.
- **`build-and-test`** (**non-blocking**) — `xcodegen generate` + `xcodebuild test` (the app XCUITests), retry-tolerant, uploads the `.xcresult` on failure. Kept out of required checks while hosted-runner XCUITest reliability is being proven.
`test-core` and `build-and-test` cache the reconstituted `external/SwiftTerm` (keyed on the pin + patch); no Metal-toolchain guard is needed — the build is Metal-free (`retire-metal-renderer`). `pr-lint.yml` enforces Conventional Commit **PR titles** (pull requests only). The workflows call `scripts/bootstrap-swiftterm.sh` directly (not `make`). Release/notarization are **not** in CI (deferred). Current CI truth: `test-core` is green and gate-worthy; `build-and-test` is non-blocking with the menu-clobber fix confirmed on CI and 2 residual rig fragilities (find-bar marker-wrap on the runner's ~72-char prompt; multi-line paste on bash-3.2) deferred to a harness-truthing successor. Full investigation record + expected-difference matrix: `research/03-analysis/github-actions-ci-cd.md`.

## Product values (hard requirements)

- **Lean memory** — nowhere near Warp; bound scrollback, manage the glyph atlas, avoid retain cycles.
- **No account / no login, free and open, no paywalled features.**
- **Native macOS feel**; keep the user's existing zsh/tmux/dotfiles working.
- **Great host for agent CLIs** (Claude Code, etc.) — agents pluggable/local, not vendor-locked.

Signature features: at-a-glance per-session progress sidebar (from OSC 133); a *lightweight* in-terminal file/diff view (not a full IDE). Full list: `research/03-analysis/xtty-requirements.md`.

## How to work here

- **Implementation follows the phased plan** in `research/04-design/02-milestones.md` (P0 skeleton → P5 daily-driver → **P7 OSC capture (keystone)** → P8 sidebar → P10 polish). P8/P9 depend on P7.
- **Use OpenSpec for non-trivial changes** (see the OpenSpec workflow section below). The project `context` in `openspec/config.yaml` is shown to the AI on every artifact.
- **Research is background, not spec.** `research/` records *why*; `openspec/specs/` will record *what is true*. When they conflict once code exists, specs win.
- **Write up research in `research/` when it's done.** Whenever an investigation or spike produces durable findings — a tooling landscape, a comparison, an internals discovery, a dead end worth remembering — capture it as a `research/` doc *as soon as it settles* (even mid-build), in the right subfolder (`03-analysis/` for analysis, `02-internals/` for internals, `04-design/` for build-plan shifts). Follow the research-doc conventions (Provenance + Sources + ✅/❌/❓) and add it to `research/README.md`. **Capture depth — settle the *mechanism*, not just the conclusion (scaled to the finding).** Any capture with **measured claims or retired theories** carries: (1) the **mechanism/internals** (how the system actually works, with the evidence); (2) **reproducible probes** — the exact commands, what each proves *and cannot prove*, including instruments that did **not** work; (3) the **investigation record** — each retired theory as a ❌ *next to the experiment that killed it* (a fates table), so stale claims can't be cited and theories don't respawn; (4) **re-verify by effect** — how a future reader re-checks the headline claim (never a syntax/read-back check); (5) when the finding generalizes, a distilled **reusable guideline** (numbered); (6) pointers to the **evidence artifacts**. Lightweight captures (a landscape/comparison with no measurements) skip these. Exemplar: `research/03-analysis/local-network-privacy-forensics.md`. Keep the *why/landscape* in `research/`; the actionable *decision* belongs in the OpenSpec change.
- **Keep progress current when implementation lands — and keep it lean.** When a change (or a milestone's tasks) is done, update the trackers in the same session: tick the `tasks.md` checkboxes; update the change's **row in the Current-status table** (bounded: state + one-liner + detail pointer — **never a narrative paragraph**); refresh the **snapshot block** only if the milestone position or overall posture moved — and **never cache the measured test envelope there**: its single home is `packer/README.md` → Acceptance → **Current envelope** (overwrite that table + append one capped history entry instead); **append the full narrative to [HISTORY.md](HISTORY.md)** under a dated heading in the matching section; and advance the milestone state in `research/04-design/02-milestones.md`. If the change settled a refutation worth never re-litigating, add a **one-line entry** to the **Learned refutations** list — a single-sentence conclusion + the condition under which it applies + an evidence pointer; mechanism and chronology live in [HISTORY.md](HISTORY.md)/`research/`, never in the entry. If the change **retires or supersedes the mechanism an existing refutation was measured on, edit that entry in place** to state the surviving conclusion — never append a second entry about the same finding. **Then verify against disk** — `openspec list` (active changes must match the open-changes table), `ls openspec/changes/archive/` (archived changes must be marked archived, not "pending archive"), `ls openspec/specs/` (the guide carries no cached list — disk is the truth), and `packer/README.md` → Acceptance (the **Current envelope** table is the envelope's only home — a transcribed count anywhere else is drift) — and fix any tracker that disagrees with reality. Don't leave finished work looking pending or stale. The **`/xtty:capture-research`** command + **`xtty-capture-research`** skill walk this whole capture-and-reconcile checklist (place + index the research doc → reconcile the trackers → verify-against-disk). **The standard change tail — drive completion from a point-of-tick marker.** Archive + reconcile is the one recurring apply-loop procedure that lives only in this file, so it drifts out of reach of the generic `/opsx:apply` loop (measured on the `fix-osc7-hostname-reverse-dns` archive: the completion task folded archive into an implicit "on completion" clause with no procedure pointer, so the loop improvised `openspec archive` and never reached the archive skill the user expected). Give every change the same recognizable tail so the ritual reaches the checkbox-walker: (1) a **pre-archive coherence** task marked `⟶ xtty-openspec-critic (<change>)`, then (2) an **archive + reconcile** task carrying `⟶ archive-ritual`. `⟶ archive-ritual` resolves to the **committed hand-authored** procedure — the OpenSpec workflow's *"After archiving, finish the merge by hand"* + this *Keep progress current* rule + the `openspec archive` CLI — **not** to the openspec-generated `/openspec-archive-change` skill (that skill is now tracked too, but it is CLI-generated — `openspec init`/`update` can rewrite it on a version bump — so it stays an **optional accelerator**, never the stable anchor a committed task depends on). Unlike the three delegation markers, `⟶ archive-ritual` is a **procedure pointer, not an agent delegation** — the ritual runs inline and produces the very tracker edits the session must own, so there is nothing to delegate and `xtty-openspec-critic` does **not** expect an agent for it. **Pre-tick self-check:** before ticking the archive task, confirm the spec deltas merged into `openspec/specs/`, the trackers reconciled (row + snapshot + HISTORY + milestone + refutations), and verify-against-disk ran.
- **Committed agents/launchers are delegated recurring work, not run inline.** Each of the four below floods the main session with noise (build/VM logs, CI attachments, rule-checking greps, source clones) if run directly, so it's a committed, version-controlled agent or launcher instead. All four share the same shape: **two spawn scenarios** — (a) a direct user request via the launcher command or plain natural language, (b) delegation from an OpenSpec `tasks.md` task — and **one delegation boundary verb pair** — a cheap/iterate verb stays inline, an expensive/validate-accept verb is delegated. A delegate-set task in any `tasks.md` MUST carry the row's marker in the task line itself (`/opsx:apply` reads the marker at the point-of-tick, not this rule — a rule that lives only here never reaches the checkbox-walking loop).

## OpenSpec workflow

We do **spec-driven development**: formalize *what* changes as reviewable artifacts, approve, then implement. Don't write feature code straight from a chat prompt — capture it as a change first.

**The loop** (one change per milestone from `research/04-design/02-milestones.md`):

```
explore ──▶ propose ──▶ apply ──▶ archive
(think)    (artifacts) (implement) (merge into specs/)
```

**Slash commands** (preferred entry points):
- `/opsx:explore <topic>` — thinking/investigation mode. **Never implements**; may read code/clone OSS to `/tmp` for understanding and may create OpenSpec artifacts. Use it before committing to an approach.
- `/opsx:propose <name>` — create a change and generate all artifacts (`proposal.md` → `design.md` + `specs/` → `tasks.md`).
- `/opsx:apply` — implement a proposed change by walking its `tasks.md` checkboxes. This is where real code gets written.

**Underlying CLI** (`openspec`, v1.6.x):
- `openspec list` — active changes · `openspec list --specs` — established specs
- `openspec new change "<name>"` — scaffold a change
- `openspec status --change "<name>" [--json]` — artifact build order & paths
- `openspec instructions <artifact> --change "<name>" --json` — template + rules for an artifact (follow these; do NOT copy the `context`/`rules` blocks into the file)
- `openspec validate "<name>"` — validate before committing
- `openspec archive "<name>"` — on completion, merge spec deltas into `openspec/specs/`

**Artifact order & dependencies:** `proposal` → (`design` + `specs`) → `tasks`. `tasks` is the apply gate.

**Spec delta format** (in `changes/<name>/specs/<capability>/spec.md`):
- Use `## ADDED Requirements` / `## MODIFIED Requirements` / `## REMOVED Requirements`.
- `### Requirement: <name>` with **SHALL/MUST** (avoid should/may); every requirement needs ≥1 scenario.
- `#### Scenario: <name>` with **WHEN/THEN** — scenarios MUST use exactly **4 hashtags** (3 fails silently).
- A **MODIFIED** requirement MUST paste the **entire** existing block from `openspec/specs/<capability>/spec.md`, not a fragment — partial content silently loses detail at archive.

**Keeping a change coherent.** The four artifacts are a dependency chain (`proposal → design + specs → tasks`), so a requirement edit rarely lives alone. When you add/modify/remove a requirement in `changes/<name>/specs/`, walk the full per-artifact checklist in `research/03-analysis/openspec-coherence-checklist.md`, then run `openspec validate "<name>"` (it catches missing deltas/scenarios). The two costliest-to-miss gotchas are already stated above: scenarios need exactly 4 hashtags, and a MODIFIED requirement must paste the entire existing block.

**Lifecycle rule:** `openspec/specs/` is the source of truth and only grows via `openspec archive` after a change is implemented. In-flight work lives in `openspec/changes/<name>/`. Commit proposal artifacts as `docs(openspec): …`; commit the implementation under the relevant `feat`/`chore` scope.

**After archiving, finish the merge by hand:** `openspec archive` merges spec deltas mechanically, so check the result before committing — (1) fill in the `## Purpose` of any **newly-created** spec (archive stubs it with `TBD - … Update Purpose after archive.`); (2) make the merged requirement text reflect *what actually shipped*, not what the proposal guessed (specs record what is true — e.g. correct the delta if the implementation diverged); (3) `openspec validate --all --type spec` and skim the diff for collapsed blank lines. Then commit as `docs(openspec): archive …`.

## Conventions

- **Commits: [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/)** — `type(scope): description`. Types used so far: `docs` (research/design/openspec content), `feat`/`test` (implementation), `chore` (tooling). Scopes: `research`, `design`, `openspec`, `app`. End commit messages with the `Co-Authored-By` trailer when authored with an AI.
- **Research docs** carry a **Provenance** note (date + how produced) and a **Sources** list; fact-checked claims use ✅/❌/❓. Snapshots are dated and time-sensitive — re-verify versions/latency/pricing before quoting.
- **Engineering bias:** macOS-first; **reuse battle-tested components over hand-rolling** (especially the VT parser — use the Williams state machine via a library); favor **latency and low memory** in every tradeoff.
- **Don't track local tooling — except the version-controlled workflow tooling:** `.claude/` is gitignored **except** two committed sets. (1) This project's own **hand-authored** tooling — `.claude/commands/xtty/` + `.claude/skills/xtty-*/` + `.claude/agents/xtty-*` (the `/xtty:capture-research` command + the `xtty-capture-research` skill + the `xtty-test-validator` agent + its `/xtty:validate` launcher command + the `xtty-ci-investigator` agent + its `/xtty:investigate-ci` launcher command + the `xtty-openspec-critic` agent + its `/xtty:review` launcher command + the `/xtty:research` source-research launcher command — worker is a Workflow, no standing agent). (2) The **openspec-generated** workflow tooling — `.claude/commands/opsx/` + `.claude/skills/openspec-*/` — tracked but **pinned to a recorded CLI version** (the `generatedBy` stamp each file carries), so a fresh clone has the `/opsx:*` workflow present and its prompt text can't drift under a silent CLI bump: regenerate it *only* via the explicit `openspec init`/`update` step and **re-commit the diff deliberately** on a version bump (routine `openspec list`/`validate`/`status` are proven to leave the files byte-identical, so day-to-day work produces no spurious diffs). Only machine-local Claude files — `settings.local.json` and runtime locks — stay ignored.
