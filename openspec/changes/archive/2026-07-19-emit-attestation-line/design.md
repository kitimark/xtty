## Context

The archive gate's attestation line is the one place a human hand-types three long hex values into `tasks.md`. Two of those values already exist inside committed deterministic tooling at the moment the human needs them: `scripts/cross-review-digest.sh` computes `B` (the parent of the proposal-introducing commit) as an intermediate and discards it, and prints the digest bare on stdout; `head` is one `git rev-parse HEAD` away. The recent incident (the attestation now recorded on `pin-cross-review-pass-c-fable`, reviewed 2026-07-19) showed what the gap costs: the human asked an AI three times to assemble the line, the AI refused three times per the HUMAN-ONLY rule, and the human then hand-typed all three values — with the `base=`/`head=` fields never mechanically verified by step-0's four checks, so any transcription path (including bytes that transited a model's chat output) is an unverified link in the attested value chain. The fix is to make the committed tool — already the trust anchor for the digest — emit the whole ready-to-paste line, and stop there.

One structural constraint shapes the implementation: `scripts/cross-review-scope.sh` carries the same base-resolution block as the digest script, and both files carry a comment requiring the block to stay **byte-identical** across the pair. This change must not touch that block. It doesn't need to: all new code consumes the already-computed `$B` and the already-computed digest *after* the existing pipeline, so the mirrored block is untouched in both files and the invariant survives without a mirror edit. (Migration includes a diff-the-blocks check to prove it.)

This change is itself in scope for the cross-review + human-attestation gate (it touches a `scripts/` path, outside the docs allowlist), and per the established spec rule the gate's recompute runs against the **reviewed-base version** of the digest script — so this enhancement cannot self-validate its own archive.

## Goals / Non-Goals

**Goals:**

- Emit the fully-assembled attestation line — `<!-- cross-review-attestation: base=<B> head=<HEAD> digest=<sha256> reviewed=<date> -->` — from `scripts/cross-review-digest.sh`, with every field filled in from the same computation that produces the digest.
- Preserve the default stdout contract **byte-identical**: a zero-flag invocation prints the bare 64-hex digest and nothing else on stdout, forever. The step-0 recompute-and-string-equals check consumes this via command substitution, and — per the G-GATE finding that the four checks are prose a model re-types — a re-typed procedure will not adapt to a changed contract; the contract must not move under it.
- Codify the output-only boundary as one ADDED `SHALL` requirement in `openspec/specs/cross-model-review/spec.md`, so the rejection below is load-bearing spec text, not a comment.

**Non-Goals — permanently rejected, not deferred:**

- **Level 2 (the tool writes the line into `tasks.md`), Level 3 (the tool ticks the attestation checkbox), Level 4 (the tool commits)** are rejected, recorded as a rejection: a committed script performing any of those acts converts the one genuinely forbidden act — self-attestation — into a routine command invocation nobody would notice crossing the line, and git cannot attribute *who* invoked a script, so the resulting commit is indistinguishable from a deliberate human act. Level 1 (print and stop) is the entire scope.
- No changes to `scripts/cross-review-scope.sh`, to archive step-0 or its four checks, to review Passes A/B/C, or to the `/xtty:cross-review` protocol. No new file-write capability in any committed tooling.
- No **new** test machinery (no new fixture suite created for the digest script) — validation is primarily by-effect against the live repo (Migration). One exception, forced by cross-review (Pass B): `scripts/test-cross-review-scripts.sh` already existed pre-change as the digest/scope scripts' regression fixture suite, so extending it with three scenarios covering `--line`'s shape/values/non-mutation, the default path's stderr silence, and trailing-argument rejection is coverage of capabilities the existing harness didn't yet know about, not new machinery.

## Decisions

**D1 — A flag on the existing script, not a sibling script.** The assembled line is made of exactly the values this script already computes (`$B`, the digest) or can derive in one call (`git rev-parse HEAD`, `date`). A sibling emitter would have to re-derive `B`, which means duplicating the base-resolution block a *third* time and widening the byte-identical mirroring invariant from a pair to a triple — pure drift surface. It would also split the trust story: the spec's verbatim instruction is that the human "runs the committed deterministic reviewed-state digest tool themselves," singular; one tool, one trust surface. (`cross-review-scope.sh` is not a precedent for splitting — it exists because *classification* is a different function, not because one function was spread across two files.) The "keep the digest tool's contract minimal" concern is real but is satisfied by D2: the contract that matters — default stdout — does not change by a byte.

**D2 — Output design: default stdout frozen and default stderr silent; `--line` is the sole, unconditional way to obtain the assembled line.** Concretely, the tail of the script changes from piping straight to `shasum` into capturing the digest:

- `DIGEST="$(digest_stream | shasum -a 256 | awk '{print $1}')"`; `head` and `reviewed` are each resolved once into their own variables (`HEAD_SHA`, `REVIEWED_DATE`) rather than inlined as nested command substitutions inside the `LINE=` assignment — a bare `VAR="...$(cmd1)...$(cmd2)..."` assignment's exit status under `set -e` is that of the *last* substitution only (verified empirically), so an earlier failing substitution (e.g. a `git rev-parse HEAD` that somehow fails) would silently yield an empty field instead of aborting; separate assignments with explicit `|| die` close that gap. `HEAD_SHA` is captured once, immediately after the dirty-tree check, and reused both for the digest traversal (`git diff --name-only "$B".."$HEAD_SHA"`, `git show "$HEAD_SHA:$p"`) and for the emitted `head=` field — reading `HEAD` twice (once mid-traversal, once for the emitted field) could otherwise bind a digest from one snapshot to a `head=` from a different one if a commit landed in between; a final re-check (`git rev-parse HEAD` still equals `$HEAD_SHA`, tree still clean) refuses rather than emit a torn line.
- Default invocation: print `$DIGEST` to stdout (unchanged bytes) and **nothing else, on either stream, ever** — this is the FINAL design, reached in two steps. Round 1 shipped an always-on stderr emission of the line; round 2's own cross-review (Pass B high, Pass C medium — a two-model consensus) found that an AI permitted under D4 to run the plain script "as engineering" would have the ready-to-paste line land in its own tool-result/transcript on every run, unasked, recreating the model-mediated-value-in-a-transcript risk one hop removed. The revision shipped in response — gating the emission on `[ -t 2 ]` (an interactive terminal) — was itself then demonstrated insufficient by round 2's OWN cross-review pass (both Pass B and Pass C independently reproduced the gap, disagreeing only on severity): `[ -t 2 ]` detects a terminal *transport*, not a human actor, and a PTY-wrapped invocation (an agent runner, `script(1)`, tmux) satisfies it without a human watching. Rather than attempt a third heuristic, the fully-closing fix was adopted: never emit the line on the default path, unconditionally, full stop — the only reliable boundary is not emitting it unasked at all. `--line` remains the sole path to the line, discoverable via the header comment, task 2.2, and D4's redirect, not "a flag nobody knows about."
- `scripts/cross-review-digest.sh --line <change>`: print **only** `$LINE` to stdout, for `| pbcopy`. Parsed as an optional leading flag before the existing positional; the script now also rejects any unexpected trailing positional (`[ $# -eq 0 ] || die "unexpected extra argument(s)"` after consuming the change name) rather than silently ignoring it — a misplaced `--line` after the change name used to do nothing detectable.
- `digest_stream`'s reviewed-path enumeration captures `git diff --name-only`'s output into a checked variable before the loop, rather than piping it in via process substitution — a process substitution's producer exit status is not propagated to the consuming loop, so a failing `git diff` could otherwise silently drive zero iterations and let an empty-input digest exit 0, as if there were no reviewed content at all (round 2, Pass B). `clean_tree()` likewise captures `git status --porcelain`'s own exit status rather than only inspecting its stdout, so an operational `git status` failure is not silently read as "the tree is clean" (round 2, Pass B).

One mechanism note that confirms the emitted `head` is the right value: the human pastes the line and *then* commits the `tasks.md` edit, so the recorded `head` is the parent of the attestation-recording commit — exactly what `git rev-parse HEAD` yields at emission time, and exactly the pattern in both existing recorded attestations (e.g. `bound-the-agents-md-guide`: `head=8472ea0…`, attestation recorded in `dc1cf83`, whose parent is `8472ea0…`).

**D3 — `reviewed=$(date +%F)` is accepted non-determinism, confined to the convenience line.** The tool's headline property — the digest is a pure function of committed git state — is untouched: the date appears only in the assembled line, never in the digest input stream. The `reviewed=` field is a human-legibility timestamp; none of step-0's four checks compare it mechanically (well-formedness checks its *shape*, not its value), and semantically it records *when the human reviewed* — an inherently time-bound fact, so a value that varies by run-day is the correct value, not noise. Alternatives rejected: leaving `reviewed=` blank for the human to fill reintroduces exactly the hand-editing this change removes; deriving the date from HEAD's commit timestamp is deterministic but wrong (it attests when code was committed, not when the human reviewed, and can be arbitrarily stale). Local `date +%F` (not UTC) matches the human's calendar day and both existing recorded lines. One interaction to state plainly: the emitted line is a fresh product of each run — a human who already pasted must not "refresh" the line on a later day, because exempt-by-act (`adds==1 && dels==0`) correctly refuses a modified attestation line. The tool emits; the paste binds.

**D4 — An AI may run the script (any mode) as engineering; it must still refuse to hand the human the line for attestation.** Running a read-only deterministic diagnostic is the same class of act as `openspec validate` — forbidding model *invocation* would be an unenforceable advisory rule (git cannot tell which terminal ran it), precisely the kind this project has measured being overridden. The boundary stays where the spec already draws it, on the HUMAN-ONLY rule: the model may not tick the task and may not *derive the attested value for the human* — so a model asked "give me the attestation line" still refuses, exactly as in the incident, but the refusal now carries a one-command redirect: *run `scripts/cross-review-digest.sh --line <change>` yourself and paste from your own terminal*. Bytes pasted from a model transcript would reintroduce the model-mediated step one hop removed; bytes pasted from the human's own terminal, produced by the committed tool, have no model in the chain. The new spec requirement constrains the *tool's* capabilities (never write/tick/commit); the *who-pastes* rule rides the existing HUMAN-ONLY text unchanged. D2's final decision (never emit the line on the default path, full stop) closes the specific accidental-exposure channel round 1 shipped and round 2 found still leaking (a model's routine, unsolicited invocation of the plain script surfacing the line in its own tool-result) — but it does **not**, by itself, make every appearance of the line human-sourced: a model *can* still run `--line` itself (D4 permits running the tool; it forbids only handing the *result* to the human as an attestation), and the line would then sit in that model's own transcript just as surely as the round-1 always-on emission did. The mechanism closes the *accidental* channel; the *deliberate* one — a model choosing to run `--line` and relay its output — is closed only by the model's own refusal, same as before this change existed. The provenance rule ("source a pasted line only from a command you ran yourself") is what actually carries that boundary, and it now has two surfaces a human reads at the point of attestation, not just this design doc: the script's own header comment, and task 2.2's text in `tasks.md`.

## Risks / Trade-offs

- **Affordance gradient.** Emitting the line lowers the cost of the next lowering: today print, tomorrow `--record`. Level 1 does not cross the boundary because it changes no file — every act that *constitutes* attestation (the paste into `tasks.md`, the tick, the commit) remains a deliberate human act, and all four step-0 checks (existence, digest equality, clean tree, exempt-by-act) operate on surfaces this tool still never touches. The line the tool prints has zero force until a human binds it by pasting and committing.
- **A future contributor adds Level 2/3 without re-deriving this reasoning.** The trail is made load-bearing, not advisory: (1) the ADDED spec requirement states the tool SHALL emit only and SHALL NOT write `tasks.md`, tick, or commit — so any Level-2/3 attempt must carry a MODIFIED/REMOVED delta on that requirement, which drags it through cross-review and the human attestation gate as an explicit, reviewable act rather than a quiet script edit; (2) a short comment at the emission site in the script points at the requirement and this design; (3) this section records *why* (the routine-invocation + non-attribution argument), so the rejection can be re-read, not just re-discovered. This follows the project's measured lesson that a rule on one advisory surface gets overridden — the spec delta at least forces the override to be explicit and gated.
- **Date non-determinism confuses a future reader** who diffs two `--line` runs across days and suspects the tool broke. Mitigated by D3's confinement (stdout digest stays bit-identical across those same two runs — the discriminating check) and by the header comment documenting the line as convenience output.
- **The default path never emits the line at all, so a human who doesn't know about `--line` gets no on-ramp to the convenience.** Judged acceptable and, after round 2, unavoidable: a TTY-based on-ramp was tried and demonstrated bypassable (see D2), and there is no reliable signal short of "did a human ask for this" — which is exactly what `--line` is. Discoverability rides the header comment, task 2.2, and D4's redirect text instead of an ambient hint. Step-0's recompute reads stdout via substitution regardless, so this was always invisible to the one machine consumer.
- **Format drift between the emitted line and what step-0's well-formedness check expects.** The format string is copied byte-for-byte from the spec's delimited-line shape and validated by-effect in Migration against the two already-recorded attestations; there is no second implementation of the format to drift against (D1's one-tool argument again).
- **A concurrent commit landing mid-computation could have bound a digest from one snapshot to a `head=` from a different one, and a failing `git rev-parse HEAD` could have been silently masked by `set -e`'s last-substitution-wins rule inside a combined assignment.** Both raised by cross-review (Pass B) and closed: `HEAD_SHA` is captured once via its own checked assignment (`HEAD_SHA="$(git rev-parse HEAD)" || die ...`) and reused for every subsequent git operation and the emitted field, with a final re-check that HEAD and tree cleanliness didn't move before any output is produced.
- **A failing `git diff` (reviewed-path enumeration) or a failing `git status` (cleanliness check) could each have been silently swallowed** — the former because a process substitution's producer exit status isn't propagated to the consuming loop (an empty enumeration would just look like "no reviewed files," not an error), the latter because `[ -z "$(cmd)" ]` reads empty-on-failure the same as empty-on-success. Both raised by cross-review round 2 (Pass B) and closed: `git diff`'s output is captured into a checked variable before the loop runs; `clean_tree()` captures `git status`'s own exit status before testing its output.
- **A newline embedded in a reviewed file's name** would make `git diff --name-only`'s line-oriented output ambiguous to a line-based reader (Pass B, round 2) — considered and explicitly NOT addressed: creating such a filename requires the same repo-write access as any more direct attack on the reviewed content, which this gate's own documented threat model already treats as an accepted residual (`research/03-analysis/cross-review-gate-defect-forensics.md`: these mechanical checks are accident tripwires, not adversarial guarantees; resistance rests on the human reading the ledger). Hardening path enumeration against a hostile filename is out of proportion to a gate that doesn't claim to resist one.

## Migration Plan

1. **Edit `scripts/cross-review-digest.sh`** per D2: capture the digest into a variable, add the `--line` flag parse plus trailing-extra-argument rejection, pin `HEAD_SHA`/`REVIEWED_DATE` into their own checked variables and reuse `HEAD_SHA` throughout `digest_stream`, assemble `$LINE`, emit per-mode — default prints only the digest, `--line` prints only the line, unconditionally either way. Header comment updated (usage, output contract, the Level-2/3 rejection pointer, the paste-provenance rule). No edit inside the shared base-resolution block.
   - *Development friction to plan around:* the script refuses on a dirty tree, and editing the tracked script itself dirties the tree — so an uncommitted edit cannot be exercised against this repo. Iterate in a scratch clone (`git clone . /tmp/xtty-scratch` gives full history, so base resolution works), then apply and commit here.
   - *Round 2:* this change's own `/xtty:cross-review` found the always-on-stderr exposure (Pass B/C consensus), the task-2.2 reviewed-base gap (Pass B), the unpinned-HEAD/masked-failure risk (Pass B), and the missing `--line` regression coverage (Pass B) — fixed in a follow-up commit with a `[ -t 2 ]` TTY-gate for the stderr exposure, re-verified by-effect (stdout still byte-identical, base-resolution block still byte-identical, `--line` shape/values still correct, `scripts/test-cross-review-scripts.sh` 21/21 green).
   - *Round 2's own re-review (bounded final round):* found the TTY-gate itself bypassable (a PTY-wrapped invocation satisfies `[ -t 2 ]` without a human watching — Pass B and Pass C both reproduced this), plus a `git diff`/`git status` failure-swallowing gap and a non-executable task 2.2 command (Pass B), plus wording drift (Pass C). Fixed: dropped the TTY-gate for the fully-closing never-emit-by-default design; captured-and-checked `git diff`/`git status` exit status instead of relying on process-substitution/empty-string propagation; rewrote task 2.2's command to be genuinely self-contained (and, in testing it, independently caught a real zsh footgun — `"$B:path"` is silently mangled by zsh's colon-modifier expansion, `"${B}:path"` is not); corrected the spec/design wording drift. Re-verified by-effect again in a fresh scratch clone.
2. **Prove the default contract is byte-identical:** at the same clean HEAD, run the pre-change script from git (`git show <parent>:scripts/cross-review-digest.sh > /tmp/old.sh; bash /tmp/old.sh <change>`) and the new script against the same change; stdout must be byte-identical (and stderr may differ — that's the feature).
3. **Prove the mirrored block is untouched:** diff the base-resolution blocks of `cross-review-digest.sh` and `cross-review-scope.sh`; still byte-identical.
4. **Validate the assembled line by-effect, two ways** — this repo's own convention (attest, then archive, back-to-back) means an attested change is archived almost immediately, so no active change ever stays around long enough to diff a live recorded line against (both changes originally cited here, `pin-cross-review-pass-c-fable` and `bound-the-agents-md-guide`, were archived by the time this task ran). **Shape**: compare the emitted line's delimiter syntax, field names, and ordering byte-for-byte modulo field values against an already-recorded line read directly from an archived change's `tasks.md`. **Values**: on a still-active change, confirm `head=` equals the current `git rev-parse HEAD`, `digest=` equals the same invocation's stdout digest, and `base=` matches the value `scripts/cross-review-scope.sh` computes for the same change — a mirror-integrity cross-check (the two scripts share the same base-resolution block by design, so this is not an independent source), not the load-bearing proof. The load-bearing external anchors are steps 2 (stdout identity against the pre-edit, already-trusted script) and 3 (block identity).
5. **Add the spec delta:** one `## ADDED Requirements` block in `changes/emit-attestation-line/specs/cross-model-review/spec.md` — a requirement to the effect of *Attestation-line emission is output-only*: the committed digest tool SHALL emit the assembled line (default stdout unchanged), and SHALL NOT write the line into any file, tick any checkbox, or create any commit; scenarios (4 hashtags) covering the frozen default stdout, the `--line` output, and the never-writes boundary. `openspec validate emit-attestation-line`.
6. **Standard change tail:** pre-archive coherence `⟶ xtty-openspec-critic (emit-attestation-line)`, then `⟶ archive-ritual`. This change touches `scripts/`, so the classifier will find it in scope: the cross-review + human attestation run before archive, with the gate's recompute anchored to the reviewed-base version of the digest script — the pre-change version, so this enhancement never validates its own archive.

**Rollback:** revert the script edit. Nothing parses or depends on the new output (the only machine consumer, step-0, reads the unchanged default stdout), so rollback restores the status quo exactly; the spec requirement only ever *forbids* capability, so it stays true of the reverted script too.

## Open Questions

1. **Resolved during this change's own cross-review (rounds 1 and 2).** The always-on-stderr question was real — round 1's Pass B and Pass C both independently flagged that unconditional stderr emission puts the line in a model's own tool transcript whenever it runs the plain script as permitted engineering; round 1's fix (a `[ -t 2 ]` TTY-gate) was itself then demonstrated bypassable by round 2's cross-review (a PTY-wrapped invocation satisfies the gate without a human watching — both passes reproduced this, disagreeing only on severity). Final answer: never emit the line on the default path, unconditionally — see D2. `--line` remains the sole, unconditional way to obtain it.
2. **Should step-0's well-formedness check grow a field-level cross-check of `base=`/`head=` now that they're machine-emitted?** The incident exposed that those fields are never verified; with the tool emitting them, verifying them becomes cheap. Out of scope here by the proposal's own boundary (no step-0 changes), and the gate carries known unfixed defects with a standing instruction to take findings to `/opsx:explore` rather than patch in-model — so this is recorded as a candidate successor, not folded in.
3. **What evidence could ever reopen the Level-2/3 rejection?** Proposed bar, so "permanently rejected" is falsifiable rather than dogma: (a) a demonstrated incident class that Level-1 emission provably cannot address, *and* (b) a mechanism that gives the write git-attributable human authorship — e.g. the spec's optional signed-attestation strong form becoming the default, at which point *who* invoked the writer is cryptographically answerable and the non-attribution argument dissolves. Absent both, the rejection stands; any reopening goes through `/opsx:explore` and a MODIFIED delta on the new requirement, never an in-model re-litigation.
