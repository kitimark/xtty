# Design — slim-status-surface

## Context

Measured decomposition of the current guide (all byte-slicing of `AGENTS.md` at `fbe3c9e`): file total 44,996 B; `## Current status` (L9–69) 22,613 B (50.3%); Learned refutations (L36–69) 17,367 B across 31 entries (Block A L38–58: 21 entries / 10,007 B; Block B, the cross-model/guide-gate saga, L60–69: 10 entries / 7,212 B); snapshot (L11–15) 1,716 B; open-changes table (L17–21) **298 B**; shipped table (L23–32) 3,074 B of which the Tooling row (L32) is 1,773 B (58%); established-specs pointer (L34) ~134 B. Regrowth vs the 2026-07-06 slim endpoint (28,132 B) = +16,864 B in 22 days ≈ 0.77 KB/day.

Precedent instruments and their measured results (`openspec/changes/archive/2026-07-06-slim-agents-context/probes/results.md`): V1 slim −21,548 startup tokens, 36/36; V2 (−status tables) 16/16 **with a self-recorded probe-set gap** ("no probe exercises what the tables uniquely provide"); V3 (−inoculations) regressed the retries trap **T1 to 0/2**, with one rep actively endorsing retries — the direct measurement that refutations are behaviorally load-bearing and that their removal is not.

The replacement `## Current status` section text is already drafted and measured (12,338 B, −10,275 B, ≈4.2k tokens at 2.46 B/token; all 28 distinct file pointers verified to resolve on disk). The packer Current-envelope block, the refutation compression table (per-entry verdicts + verified pointer homes), the narrowed spec delta, and the probe plan are likewise drafted; this design records the load-bearing decisions they embody.

Verification-harness coupling: **not applicable** — this is a docs/tooling change with no new observable app behavior (the sole source-tree touch is a test-file comment). Stated here so the critic's coupling flag is pre-answered.

## Goals / Non-Goals

**Goals:**

- Restore the refutations tier to the measured-validated shape (one-line conclusion + applicability + pointer) without losing any inoculation.
- End the cached-envelope drift class at its source: one current-truth block in `packer/README.md`, a pointer in the guide, and a spec ratchet forbidding the cache.
- Correct the confirmed-false "56-test envelope identical across all 5 environments" claim everywhere it appears.
- Rebound the shipped table's Tooling row to the ratified category-keyed shape.
- Prove no behavioral regression before landing, against a freshly frozen baseline.

**Non-Goals:**

- No second guide or refutations register (spec-forbidden); no deletion of any content from the repository.
- No new agent, command, skill, or `make` target; no product behavior change; no re-litigation of what the refutations say.
- No removal of the open-changes table, the snapshot, the five closed phase rows, or the established-specs derive-on-demand line.

## Decisions

**D1 — Compress the refutations; never pointerize them.** Two ratified specs forbid the alternative (`research-capture:86` "not as bare pointers"; `agent-guide-parity:9` "exactly one canonical guide"), and it is measured: V3 (list removed) regressed the retries trap to **0/2** with one rep actively endorsing retries. Compression *toward* one-liners moves the file toward conformance — 20 of 31 current entries exceed "one-line statement" — so the compression itself needs no delta; the delta this change carries is a ratchet against re-accretion, not a permission slip.
*Alternatives rejected:* (a) a `REFUTATIONS.md` second file — spec-forbidden, and it recreates the "doesn't know there is something to look up" failure mode; (b) leave the list alone and cut only tables — the tables are ~3.4 KB against 17.4 KB.

**D2 — Three compression tiers, assigned by measured evidence, not by length.**
- *Keep byte-for-byte* (11 entries, 1,756 B): already ≤200 B one-liners — adding pointers would **grow** them 35%. Includes E1 (`retry-ban`), which is **frozen**: it is the only entry with an ablation result (V3 T1 0/2), so any edit re-opens the T1 gate.
- *Compress* (10 entries, 8,251 → ~3,900 B): each dropped clause re-verified as homed elsewhere (per-entry table in the compression audit). Carve-outs: E9 (`env-seed-wall`) stays verbatim + gains a pointer — its only other home is one blockquote inside a 96 KB doc; E14's enumeration of the four refuted Local-Network routes stays complete, because *the four names are the inoculation*; E19 (`cgevent-scroll-dropped`) ships keep-medium with its sign clause inline (see D3); E20's `smkx` token stays inline (its other homes carry the mechanism but a terminfo-name grep should still land here).
- *Merge* (10 → 3 entries, 7,212 → ~2,551 B): the cross-model/guide-gate cluster contains one near-verbatim duplicate pair (`:60` ⊃ `:69`, 805 B recoverable at zero loss), two parallel-instance pairs, and three items of one do-not-reintroduce list. One wrong pointer is fixed in the merge: the "instructed writing" claim's real home is `HISTORY.md`, not `agents-md-structural-best-practices.md` (0 occurrences there).
*Alternative rejected:* delete the cluster outright — that is the **A-0** ablation arm; if A-0 passes the cross-model traps, the merge floor can be revisited at content granularity only, never at gate granularity.

**D3 — Rehome the orphaned fact before compressing its entry, and keep the sign clause inline too.** The `CGEvent` `wheel1` sign-inverse note has zero occurrences outside `AGENTS.md:56` (`App/PaneController.swift:578` uses the field without documenting sign; the XCUITest half *is* homed at `AppUITests/XttyMouseWheelUITests.swift:26–32`). It moves into that existing sign-convention comment — where a future editor of the convention actually reads — and the compressed E19 entry retains the one-line sign clause (keep-medium), so the fact is doubly homed rather than moved-and-hoped. Comment-only: a build check is sufficient and inline-permitted (`test-validation:66`).
*Alternative considered:* park it in `packer/README.md` — rejected: wrong audience.

**D4 — Both tables stay; only the Tooling row changes shape.** *(This resolves the one fork between the drafting passes, in favor of keeping the table.)*
- *Open-changes table (298 B): kept as a table.* It is what the ratified spec names ("a tabular per-change entry", `research-capture:48`; scenario `:81`), it is 1.3% of the section, and it is the only element whose removal would require **both** a spec-text change and a never-before-tested probe class (cold-session open-changes orientation) to pass. Keeping it makes the entire drafted section compliant under the current ratified spec, deletes that probe-risk class outright, and sacrifices ~300 B of the ~10.3 KB saving. The "must match `openspec list`" verification duty is preserved verbatim. If table-maintenance friction ever recurs, pointerizing it is a small follow-up change — the orientation probes are already designed and on file in this change's probe plan.
- *Shipped table: keep the 5 closed phase rows, rebound the Tooling row.* Deleting the table would make `coherence-review:30–33` vacuous (no category-keyed row left to police) and would drop ~1.1 KB that usefully compresses a stale 51 KB milestones file. The Tooling row (1,773 B mini-index) is already non-compliant with the ratified category-keyed bound — collapsing it to a category summary + `HISTORY.md`/`research/README.md` pointers needs no delta. All 14 doc names dropped from the mini-index are verified indexed in `research/README.md`.
*Alternative rejected:* pointerize the open-changes table behind a delta clause ("the active-change list SHALL NOT be transcribed") with a probe-gated restore contingency — strictly dominated: it needs a spec change, an untested probe class, and a contingency plan, to save 298 bytes.

**D5 — The packer envelope block is a contract, not a cleanup.** Today `packer/README.md:299` leads `### Acceptance` with `Envelope: 40/1/1 of 42` (2026-07-07, six supersessions stale) while the current figures sit at `:650–668`; the only string reading "current authoritative envelope" (`:603`) points at a **superseded** figure (`54/0/1` of 55 — which is nonetheless the last full-VM-measured figure and stays honestly labelled as such). Replacing AGENTS.md's cache with a pointer to that section without fixing it would point agents at a *worse* number than the cache. Hence: one overwrite-in-place **Current envelope** table keyed by (tier, golden) with a `CURRENT | STALE (n behind) | SUPERSEDED` status token, an append-only newest-first `Envelope history` log below it (entries capped, never claiming currency), and the anti-reaccretion maintenance rules (overwrite-in-place; history append-only; entry cap; the matrix carries zero numbers — its own `:675–676` rule, violated at `:683`/`:688`; status is a token; reverse duty names the table, not past changes; no current count anywhere else in the repo; projections labelled and never in the table; subset runs never envelope figures).
This also lands the substantive **F4 correction**: the "prior 56-test envelope identical across all 5 environments" claim (AGENTS.md:14, HISTORY.md:64, packer/README.md:667) is false — `:644–648` records the 56th test's change never ran the VM tiers; the last 5-environment-identical measurement is the **55**-test `54/0/1` (2026-07-10), so VM tiers are **3 tests behind across 2 changes**. Also fixed in the same pass: the Tier-1 evidence pointer (the accepted `57/0/1` is task 4.8's post-cross-review clean run, not task 4.4's bundle) and the two retired `/xtty:cross-review` references (`:618–619`, `:631`).
The validator contract is preserved: the redesign re-heads and reorders only *within* `### Acceptance`; the `### Acceptance` and matrix headings survive, envelope and matrix stay adjacent (`test-validation:35–38` is location-agnostic) — **no `.claude/agents/xtty-test-validator.md` edit, no `test-validation` delta**. Reverse duty on this project's own docs: a test/environment change keeps updating `packer/README.md` in the same session, now by overwriting the table + appending one capped history entry.
*Alternative rejected:* keep the AGENTS.md cache as a "drift detector" — it detected nothing; all three copies drifted together into the same wrong claim.

**D6 — The delta modifies exactly one requirement, pasted whole, and adds only the three ratchet clauses.** `research-capture` → "Documented capture-and-reconcile workflow with verify-against-disk" (`openspec/specs/research-capture/spec.md:40–91`). Paragraphs 1–3 are byte-identical; paragraph 4 gains three sentences: (i) a learned-refutation entry is bounded to one sentence + applicability condition + evidence pointer; (ii) retiring/superseding a refutation's mechanism edits the existing entry in place, never appends; (iii) the measured test envelope is pointed to, not cached, and the pointed-to home states its current answer plainly and up front. Scenarios: 8 existing (7 byte-identical; "Learned refutations survive the slimming" gains the bound) + 2 new ("A retired mechanism edits its refutation in place"; "The measured test envelope is pointed to, not cached") = 10. The "tabular per-change entry" wording is **untouched** — the kept open-changes table satisfies it as-is (D4). No `coherence-review` delta (`:47` permits the agent to encode only the operationalization; the agent *file* is still edited because its checks should enforce the new bounds), no `test-validation` delta, no `build-workflow` delta.

**D7 — Probe methodology reused, baseline re-frozen, one arm dropped, one probe corrected.** Harness reused from the archived suite (`measure-context.sh` byte-for-byte; `run-probe.sh`/`run-batch.sh` with two declared arm-symmetric edits: turn cap 8 → 10, and a per-probe `tools` override used only by the Bash-enabled orientation probe). Instruments: startup-token cost (gate formula `startup(S) ≤ startup(N) − 0.85 × (bytes_removed / 2.49)` with an **absolute floor of ≥3,000 tokens saved**; the archived ≥20,000 gate is explicitly not reused — unreachable at this scale; predicted ≈4.2k), `num_turns`, and a new **inline-sufficiency** extraction (was the refutation produced before any tool call), gating for the merged cross-model cluster because the archived suite proved traps can pass off secondary doc homes (`results.md:89–91`). Variants: **N** (frozen baseline at current main), **S** (the full restructure incl. the packer block), **A-R** (refutation compression only) and **A-0** (cross-model cluster deleted rather than merged) as non-gating diagnostics. The **A-T arm (tables pointerized) is dropped** — the pointerize option left the change with D4, so there is no shipping shape for it to price; the orientation probes (O1a/O1b/O2) are kept — O1a/O1b as cheap controls closing the archived suite's recorded probe-set gap, O2 gating what the Tooling mini-index uniquely provided. **Probe C1's pass criterion is corrected before freeze**: the current VM envelope ground truth is `54/0/1` of 55 on both goldens (2026-07-10, the last full VM measurement) with the VM tiers 3 tests behind across 2 changes — not the superseded `41/0/1` of 42 — and the pre-flight grep list includes `54/0/1`. Grading order prevents hindsight bias: probes + envelope committed first, N run and graded and frozen, only then S, then ablations; ambiguous/hedged = FAIL applied identically everywhere. Fix loop bounded: a trap failure is repaired by restoring that one line's conclusion clause and re-running that probe, cap 2 iterations, after which the entry ships at full length (G-TARPIT-6/7 applies to this loop too); never by restoring narrative.

**D8 — No `make status`, no `/xtty:status`.** The repo's don't-pre-build-a-speculative-roster refutation applies directly and the friction has not recurred (the existing derive-on-demand specs line has produced zero documented complaints since 2026-07-06; the kept open-changes table answers "what's in flight" from loaded context). A dumb-aggregator sketch exists in the drafting record for the day friction is observed; if ever built it parses no narrative Markdown and caches nothing.

**D9 — Three commits, ordering load-bearing.** (1) packer Current-envelope block + F4 correction + `wheel1` rehome; (2) AGENTS.md section + *Keep progress current* rule + the three tooling files + the spec delta staged in the change; (3) research capture + tracker reconcile. Commit 1 must precede commit 2 — AGENTS.md's counts may not become a pointer while the pointed-to section leads with a figure six supersessions stale. Unlike the precedent's single atomic commit (needed because AGENTS.md/HISTORY.md were two halves of one move), these halves are independently valid and independently revertable: commit 1 is a strict improvement whether or not commit 2 ever lands.

## Risks / Trade-offs

- **[A compressed refutation stops inoculating]** (the V3 failure mode: T1 0/2, one rep endorsing retries) → Trap-class gate, zero regressions tolerated; fix = restore that one line's conclusion clause, re-run that probe, cap 2 iterations then ship the entry at full length. E1 is frozen byte-for-byte so this cannot trigger on the one entry with a measured ablation.
- **[A trap passes off a secondary doc home, falsely certifying inline compliance]** — measured real in the archived suite (`results.md:89–91`) → the inline-sufficiency instrument gates the merged cross-model cluster (≥1 of 3 S-reps refutes at turn 1 with zero file reads); a miss un-merges that entry toward its pre-merge conclusion, never restores narrative.
- **[The Tooling-row collapse orphans a pointer]** → verified pre-flight: all 14 doc names dropped from the mini-index are indexed in `research/README.md`; probe O2 checks the retrieval path by effect.
- **[Ordering hazard: the guide points at a stale packer figure]** → hard sequencing (D9); a mechanical pre-flight grep of the new block for `260/0/0`, `57/0/1`, `58`, `54/0/1` before any S run — the envelope-retrieval probe cannot otherwise distinguish "pointer broken" from "guide broken".
- **[A dropped clause turns out to have no other home]** (the `wheel1` class) → the one known orphan is rehomed in commit 1 *before* compression; the per-entry home check re-runs at apply; any newly-discovered orphan goes to `HISTORY.md` or stays inline — never dropped.
- **[Context saving misses the ≥3,000-token floor]** → measured before any behavioral run; if missed, the guide half is re-scoped — but the packer block and the F4 correction stand on their own merits and are not reverted.
- **[Measured Δ disagrees with the byte prediction by >15%]** → investigate before trusting any behavioral comparison.
- **[The critic mis-checks the new shape]** → the critic edit rides commit 2 (Pass-1 category-keyed bullet extended to the refutations list; Pass-2 cached-envelope BLOCKER; stamp v7 → v8 at all three coupled sites so a stale-served definition is detectable). The existing Pass-2 table-match check stays valid because the table is kept.
- **[Probe-set gap persists]** — the traps sample ~10 of 24 surviving entries → ranked-by-blast-radius sampling, the structural backstop (nothing deleted from the repo), and a standing recurrence trigger: an observed re-proposal in a real session is fixed by restoring that one line's conclusion clause.
- **[The file re-inflates again]** → the delta's three ratchet clauses plus the critic's new checks are the mechanism. Honest limit, stated deliberately: advisory-only leanness was measured insufficient three times and this change does **not** re-propose a mechanical gate (no new evidence since `remove-guide-gate`); the G1 probe confirms the restructured guide still states both directions.
- **[Post-compaction orientation degrades]** (not cheaply A/B-testable; flagged unresolved in the precedent) → the snapshot is deliberately the one tier not pointerized beyond the envelope bullet; recorded as monitored, not claimed solved.
- **[Cross-suite comparison to 2026-07-06 is invalid]** (different CLI, cap, model) → every bar is computed against the freshly frozen N; the archived numbers are cited as precedent, never as a bar.

## Migration Plan

1. Pre-register probes + acceptance envelope; freeze the N baseline (graded and committed) before any S content lands anywhere.
2. Land commit 1 (packer Current-envelope block + F4 correction + `wheel1` rehome) on main — independently valuable.
3. Author S in a worktree (AGENTS.md section + rule + tooling files + delta); mechanical pre-flight checks; measure context; run the gated S arm + ablations; apply the bounded fix loop.
4. Land commit 2 (guide + tooling + delta staged in the change), then commit 3 (research capture + trackers).
5. Rollback: `git revert` of commit 2 restores the fat status section exactly; commit 1 is not reverted with it.
