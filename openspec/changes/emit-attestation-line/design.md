## Context

The archive gate's attestation line is the one place a human hand-types three long hex values into `tasks.md`. Two of those values already exist inside committed deterministic tooling at the moment the human needs them: `scripts/cross-review-digest.sh` computes `B` (the parent of the proposal-introducing commit) as an intermediate and discards it, and prints the digest bare on stdout; `head` is one `git rev-parse HEAD` away. The recent incident (the attestation now recorded on `pin-cross-review-pass-c-fable`, reviewed 2026-07-19) showed what the gap costs: the human asked an AI three times to assemble the line, the AI refused three times per the HUMAN-ONLY rule, and the human then hand-typed all three values — with the `base=`/`head=` fields never mechanically verified by step-0's four checks, so any transcription path (including bytes that transited a model's chat output) is an unverified link in the attested value chain. The fix is to make the committed tool — already the trust anchor for the digest — emit the whole ready-to-paste line, and stop there.

One structural constraint shapes the implementation: `scripts/cross-review-scope.sh` carries the same base-resolution block as the digest script, and both files carry a comment requiring the block to stay **byte-identical** across the pair. This change must not touch that block. It doesn't need to: all new code consumes the already-computed `$B` and the already-computed digest *after* the existing pipeline, so the mirrored block is untouched in both files and the invariant survives without a mirror edit. (Migration includes a diff-the-blocks check to prove it.)

This change is itself in scope for the cross-review + human-attestation gate (it touches a `scripts/` path, outside the docs allowlist), and per the established spec rule the gate's recompute runs against the **reviewed-base version** of the digest script — so this enhancement cannot self-validate its own archive.

## Goals / Non-Goals

**Goals:**

- Emit the fully-assembled attestation line — `<!-- cross-review-attestation: base=<B> head=<HEAD> digest=<sha256> reviewed=<date> -->` — from `scripts/cross-review-digest.sh`, with every field filled in from the same computation that produces the digest.
- Preserve the default stdout contract **byte-identical**: a zero-flag invocation prints the bare 64-hex digest and nothing else on stdout, forever. The step-0 recompute-and-string-equals check consumes this via command substitution, and — per the G-GATE finding that the four checks are prose a model re-types — a re-typed procedure will not adapt to a changed contract; the contract must not move under it.
- Codify the output-only boundary as one ADDED `SHALL` requirement in `openspec/specs/cross-model-review/spec.md`, so the rejection below is load-bearing spec text, not a comment.

**Non-Goals — permanently rejected, not deferred:**

- **Level 2 (the tool writes the line into `tasks.md`), Level 3 (the tool ticks the attestation checkbox), Level 4 (the tool commits)** are rejected, recorded as a rejection: a committed script performing any of those acts converts the one genuinely forbidden act — self-attestation — into a routine command invocation nobody would notice crossing the line, and git cannot attribute *who* invoked a script, so the resulting commit is indistinguishable from a deliberate human act. Level 1 (print and stop) is the entire scope.
- No changes to `scripts/cross-review-scope.sh`, to archive step-0 or its four checks, to review Passes A/B/C, or to the `/xtty:cross-review` protocol. No new file-write capability in any committed tooling.
- No new test machinery (no fixture suite for the digest script) — validation is by-effect against the live repo (Migration).

## Decisions

**D1 — A flag on the existing script, not a sibling script.** The assembled line is made of exactly the values this script already computes (`$B`, the digest) or can derive in one call (`git rev-parse HEAD`, `date`). A sibling emitter would have to re-derive `B`, which means duplicating the base-resolution block a *third* time and widening the byte-identical mirroring invariant from a pair to a triple — pure drift surface. It would also split the trust story: the spec's verbatim instruction is that the human "runs the committed deterministic reviewed-state digest tool themselves," singular; one tool, one trust surface. (`cross-review-scope.sh` is not a precedent for splitting — it exists because *classification* is a different function, not because one function was spread across two files.) The "keep the digest tool's contract minimal" concern is real but is satisfied by D2: the contract that matters — default stdout — does not change by a byte.

**D2 — Output design: default stdout frozen; the line goes to stderr on every run, and `--line` prints only the line to stdout.** Concretely, the tail of the script changes from piping straight to `shasum` into capturing the digest:

- `DIGEST="$(digest_stream | shasum -a 256 | awk '{print $1}')"`, then `LINE="<!-- cross-review-attestation: base=$B head=$(git rev-parse HEAD) digest=$DIGEST reviewed=$(date +%F) -->"`.
- Default invocation: print `$DIGEST` to stdout (unchanged bytes), then a short label plus the bare `$LINE` to **stderr** — stderr is the script's existing diagnostic channel (`die()` already writes there) and is explicitly non-contractual; exit code, not stderr silence, is the machine contract. Emitting on the zero-flag path matters because the incident's human ran the zero-flag path — a convenience hidden behind a flag nobody knows about doesn't remove the transcription step.
- `scripts/cross-review-digest.sh --line <change>`: print **only** `$LINE` to stdout, for `| pbcopy`. Parsed as an optional leading flag before the existing positional (`[ "${1:-}" = "--line" ] && { LINE_ONLY=1; shift; }`); the usage string gains the flag; all refusal paths (`dirty tree`, `range-omission`, missing dir) are unchanged and fire before any output in either mode.
- The label line on stderr is separate from the line itself so the pasteable bytes stay clean for copy.

One mechanism note that confirms the emitted `head` is the right value: the human pastes the line and *then* commits the `tasks.md` edit, so the recorded `head` is the parent of the attestation-recording commit — exactly what `git rev-parse HEAD` yields at emission time, and exactly the pattern in both existing recorded attestations (e.g. `bound-the-agents-md-guide`: `head=8472ea0…`, attestation recorded in `dc1cf83`, whose parent is `8472ea0…`).

**D3 — `reviewed=$(date +%F)` is accepted non-determinism, confined to the convenience line.** The tool's headline property — the digest is a pure function of committed git state — is untouched: the date appears only in the assembled line, never in the digest input stream. The `reviewed=` field is a human-legibility timestamp; none of step-0's four checks compare it mechanically (well-formedness checks its *shape*, not its value), and semantically it records *when the human reviewed* — an inherently time-bound fact, so a value that varies by run-day is the correct value, not noise. Alternatives rejected: leaving `reviewed=` blank for the human to fill reintroduces exactly the hand-editing this change removes; deriving the date from HEAD's commit timestamp is deterministic but wrong (it attests when code was committed, not when the human reviewed, and can be arbitrarily stale). Local `date +%F` (not UTC) matches the human's calendar day and both existing recorded lines. One interaction to state plainly: the emitted line is a fresh product of each run — a human who already pasted must not "refresh" the line on a later day, because exempt-by-act (`adds==1 && dels==0`) correctly refuses a modified attestation line. The tool emits; the paste binds.

**D4 — An AI may run the script (any mode) as engineering; it must still refuse to hand the human the line for attestation.** Running a read-only deterministic diagnostic is the same class of act as `openspec validate` — forbidding model *invocation* would be an unenforceable advisory rule (git cannot tell which terminal ran it), precisely the kind this project has measured being overridden. The boundary stays where the spec already draws it, on the HUMAN-ONLY rule: the model may not tick the task and may not *derive the attested value for the human* — so a model asked "give me the attestation line" still refuses, exactly as in the incident, but the refusal now carries a one-command redirect: *run `scripts/cross-review-digest.sh --line <change>` yourself and paste from your own terminal*. Bytes pasted from a model transcript would reintroduce the model-mediated step one hop removed; bytes pasted from the human's own terminal, produced by the committed tool, have no model in the chain. The new spec requirement constrains the *tool's* capabilities (never write/tick/commit); the *who-pastes* rule rides the existing HUMAN-ONLY text unchanged.

## Risks / Trade-offs

- **Affordance gradient.** Emitting the line lowers the cost of the next lowering: today print, tomorrow `--record`. Level 1 does not cross the boundary because it changes no file — every act that *constitutes* attestation (the paste into `tasks.md`, the tick, the commit) remains a deliberate human act, and all four step-0 checks (existence, digest equality, clean tree, exempt-by-act) operate on surfaces this tool still never touches. The line the tool prints has zero force until a human binds it by pasting and committing.
- **A future contributor adds Level 2/3 without re-deriving this reasoning.** The trail is made load-bearing, not advisory: (1) the ADDED spec requirement states the tool SHALL emit only and SHALL NOT write `tasks.md`, tick, or commit — so any Level-2/3 attempt must carry a MODIFIED/REMOVED delta on that requirement, which drags it through cross-review and the human attestation gate as an explicit, reviewable act rather than a quiet script edit; (2) a short comment at the emission site in the script points at the requirement and this design; (3) this section records *why* (the routine-invocation + non-attribution argument), so the rejection can be re-read, not just re-discovered. This follows the project's measured lesson that a rule on one advisory surface gets overridden — the spec delta at least forces the override to be explicit and gated.
- **Date non-determinism confuses a future reader** who diffs two `--line` runs across days and suspects the tool broke. Mitigated by D3's confinement (stdout digest stays bit-identical across those same two runs — the discriminating check) and by the header comment documenting the line as convenience output.
- **Stderr emission surprises a caller that captures stderr.** No known caller treats stderr output as failure (the contract is the exit code; `die()` already emits stderr on refusals), and step-0's recompute reads stdout via substitution — the extra stderr text is invisible to it. If a stderr-sensitive caller ever appears, demoting the always-on emission to `--line`-only is a two-line, contract-preserving retreat.
- **Format drift between the emitted line and what step-0's well-formedness check expects.** The format string is copied byte-for-byte from the spec's delimited-line shape and validated by-effect in Migration against the two already-recorded attestations; there is no second implementation of the format to drift against (D1's one-tool argument again).

## Migration Plan

1. **Edit `scripts/cross-review-digest.sh`** per D2: capture the digest into a variable, add the `--line` flag parse, assemble `$LINE` from `$B` / `git rev-parse HEAD` / `$DIGEST` / `date +%F`, emit per-mode. Header comment updated (usage, output contract, the Level-2/3 rejection pointer). No edit inside the shared base-resolution block.
   - *Development friction to plan around:* the script refuses on a dirty tree, and editing the tracked script itself dirties the tree — so an uncommitted edit cannot be exercised against this repo. Iterate in a scratch clone (`git clone . /tmp/xtty-scratch` gives full history, so base resolution works), then apply and commit here.
2. **Prove the default contract is byte-identical:** at the same clean HEAD, run the pre-change script from git (`git show <parent>:scripts/cross-review-digest.sh > /tmp/old.sh; bash /tmp/old.sh <change>`) and the new script against the same change; stdout must be byte-identical (and stderr may differ — that's the feature).
3. **Prove the mirrored block is untouched:** diff the base-resolution blocks of `cross-review-digest.sh` and `cross-review-scope.sh`; still byte-identical.
4. **Validate the assembled line by-effect against `pin-cross-review-pass-c-fable`'s recorded attestation** — field-level, because commits landing after its attested head (including this change's own) widen its `B..HEAD` range and legitimately change the recomputed digest (that is the tool working as designed, not a bug; say so in the task so nobody misreads it): `base=` must string-equal the recorded `base=` (invariant per change), `head=` must equal the current `git rev-parse HEAD`, and `digest=` must equal the same invocation's stdout digest. Shape of the whole line must match the recorded lines' shape byte-for-byte modulo field values.
5. **Add the spec delta:** one `## ADDED Requirements` block in `changes/emit-attestation-line/specs/cross-model-review/spec.md` — a requirement to the effect of *Attestation-line emission is output-only*: the committed digest tool SHALL emit the assembled line (default stdout unchanged), and SHALL NOT write the line into any file, tick any checkbox, or create any commit; scenarios (4 hashtags) covering the frozen default stdout, the `--line` output, and the never-writes boundary. `openspec validate emit-attestation-line`.
6. **Standard change tail:** pre-archive coherence `⟶ xtty-openspec-critic (emit-attestation-line)`, then `⟶ archive-ritual`. This change touches `scripts/`, so the classifier will find it in scope: the cross-review + human attestation run before archive, with the gate's recompute anchored to the reviewed-base version of the digest script — the pre-change version, so this enhancement never validates its own archive.

**Rollback:** revert the script edit. Nothing parses or depends on the new output (the only machine consumer, step-0, reads the unchanged default stdout), so rollback restores the status quo exactly; the spec requirement only ever *forbids* capability, so it stays true of the reverted script too.

## Open Questions

1. **Does the always-on stderr emission earn its keep, or should the line be `--line`-only?** The argument for always-on is the incident (the zero-flag path is the one humans actually run); the argument against is stderr noise in logged/scripted contexts. Shipping both and demoting later is cheap (see Risks); the reverse — discovering nobody found the flag — is another incident.
2. **Should step-0's well-formedness check grow a field-level cross-check of `base=`/`head=` now that they're machine-emitted?** The incident exposed that those fields are never verified; with the tool emitting them, verifying them becomes cheap. Out of scope here by the proposal's own boundary (no step-0 changes), and the gate carries known unfixed defects with a standing instruction to take findings to `/opsx:explore` rather than patch in-model — so this is recorded as a candidate successor, not folded in.
3. **What evidence could ever reopen the Level-2/3 rejection?** Proposed bar, so "permanently rejected" is falsifiable rather than dogma: (a) a demonstrated incident class that Level-1 emission provably cannot address, *and* (b) a mechanism that gives the write git-attributable human authorship — e.g. the spec's optional signed-attestation strong form becoming the default, at which point *who* invoked the writer is cryptographically answerable and the non-attribution argument dissolves. Absent both, the rejection stands; any reopening goes through `/opsx:explore` and a MODIFIED delta on the new requirement, never an in-model re-litigation.
