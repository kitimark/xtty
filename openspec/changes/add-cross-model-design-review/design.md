## Context

The `coherence-review` capability delegates full coherence review to the committed Opus `xtty-openspec-critic` agent (conformance: rulebook + disk-drift; never reads product source). This change was **dogfooded through two rounds of its own tri-pass** during authoring, which is the source of most decisions below: Pass A (conformance) stayed clean and blind to soundness; Pass B (Codex/GPT) and Pass C (inline Opus soundness) each caught real feasibility bugs, and round 2 *fact-checked and refuted several plausible round-1 fixes* against the actual plugin source — the corrections here are the survivors.

Fact-checked properties of the installed Codex plugin (`~/.claude/plugins/cache/openai-codex/codex/<v>/`):
- The `status` subcommand returns **no `ready` field** and succeeds even when Codex is uninstalled/unauthenticated. The **`setup --json`** subcommand emits `ready = node.available && codex.available && auth.loggedIn` **and the individual fields** — including `auth.source` and `auth.requiresOpenaiAuth`; it connects to the Codex app-server (may block/err in a headless env). Crucially, the plugin **normalizes an app-server connect failure and a genuine logged-out state into the same `auth.loggedIn == false` shape** and exposes **no probe-success field** — "logged out" is not fully distinguishable from "app-server unreachable" in the installed plugin version.
- The review **input is the full diff** of the resolved git target; **focus text is prompt guidance, not a path filter** (the template even tells Codex to report issues outside the focus).
- The companion's `--background` flag is a **no-op for the `adversarial-review` subcommand** — it always runs foreground; only the *task* subcommands branch on background.
- The `review-output` schema requires top-level `verdict/summary/findings/next_steps` and per-finding `severity/title/body/file/line_start/line_end/confidence/recommendation` (**no `line`**, `additionalProperties:false`); it ships at `~/.claude/plugins/cache/openai-codex/codex/<v>/schemas/review-output.schema.json` (under `schemas/`, **not** `scripts/`).
- Invocation is via a **version-pinned** script path; `${CLAUDE_PLUGIN_ROOT}` is unset in a non-plugin project command; the command is `disable-model-invocation: true` (user-triggered by design).

Binding refutations: **`run_in_background` strands subagents**; **don't pre-build speculative dev-workflow machinery** (n≥several, provably under-done); **agent-definition edits reach spawns with unpredictable lag**.

## Goals / Non-Goals

**Goals:** a repeatable, terminating cross-model review (conformance ∥ two-model soundness) with a union ledger, a bounded fix→re-review loop, and **detectable** degradation; a critic hardened to fact-check *existing-code* claims.

**Non-Goals:** not per-edit; not a new standing agent (Pass C inline); not literal model agreement (gate = findings resolved); not a claim that Pass 4 catches design-*ownership* soundness (it does not — D6); no product-code / `verification-harness` change.

## Decisions

### D1 — New `cross-model-review` capability + a `coherence-review` MODIFY
Orchestrator + fix-loop is a new capability (the loop *edits* artifacts — `coherence-review` is observe-only); the code-accuracy pass MODIFIES the critic.

### D2 — Orchestration in the main loop, not a subagent
The loop drives a detached Codex call and edits artifacts between rounds; a subagent owning Codex hits the strand refutation. `/xtty:cross-review` is a main-loop protocol; the passes stay observe-only.

### D3 — Tri-pass on the real schema; consensus is a heuristic, not a mechanical join
- **Pass A** — Opus critic (conformance, + code-accuracy D6). **Pass B** — Codex/GPT soundness. **Pass C** — inline Opus soundness, **emitting the real `review-output` schema** (top-level `verdict/summary/findings/next_steps`; per-finding `severity/title/body/file/line_start/line_end/confidence/recommendation`).
- **Consensus is a heuristic confidence signal, not a "defined join."** The common schema makes B and C outputs *comparable*, but two differently-modeled reviewers diverge on title text, file attribution (a bug can be filed under `design.md`, the spec, or a product file), and line ranges — so matching "same finding" is an **irreducibly semantic judgment** made by the main-loop Opus. Flag likely-consensus findings as higher-confidence; do not claim a mechanical join.
- **Async-join:** launch B in the background **via the harness's Bash `run_in_background`** — the companion's own `--background` flag is a **no-op for `adversarial-review`** (that subcommand always runs foreground; only *task* subcommands branch on background), so the backgrounding lives in the harness, not the companion. Then run A + C as subagents, **await B's re-invoke before merging** (concurrent passes, barrier merge). `run_in_background` is safe here because the **main loop** owns the call — the strand refutation applies to subagents.

### D4 — Convergence: bounded, escalated, audited; one launch authorizes the bounded spend
A round runs A∥B∥C; the caller adjudicates each finding **fix** or **dismiss-with-recorded-rationale**, applies fixes, re-runs. **Converged** ⇐ zero unresolved actionable findings from any pass. Bound **N = 2 rounds**; on the bound, **escalate the residual to the human** (who MAY authorize continuation — as happened here). **Spend model:** a single user launch of `/xtty:cross-review` **authorizes the whole bounded run** (up to N Pass-B invocations); the loop does **not** re-prompt per round, but a *new* review requires a *new* user launch — this resolves the "auto-fires paid Codex in rounds 2..N" contradiction. **Owned honestly: this is user-initiated per *run*, not per paid call** — rounds 2..N fire the paid reviewer without a fresh per-call human action, a deliberate deviation from the plugin's per-call `disable-model-invocation` intent; we do not claim per-call user-initiation. The orchestrator SHALL **surface the full ledger — every finding, resolution, and dismissal rationale — to the human on every converged run**, not only at the bound. Every completed run SHALL also **persist that verdict + adjudicated ledger (+ coverage label) as a durable receipt** at `openspec/changes/<name>/cross-review-receipt.md` — the committed artifact the blocking pre-archive gate task and the archive precondition check (D7).

### D5 — Codex mechanics (portable, scoped, detectably-degrading) — all four fact-checked
- **Locate:** glob `~/.claude/plugins/cache/openai-codex/codex/*/scripts/codex-companion.mjs`, pick the highest version by **semver/numeric** comparison (not lexical — `1.0.10 > 1.0.6`). **No glob match (or `codex` absent from PATH) is *not* a hard failure** — it is **capability-absent** → single-model degrade (classifier arm 1 below); a fresh clone must never be blocked. (`${CLAUDE_PLUGIN_ROOT}` is unset in a project command, hence the glob.)
- **Review substrate — a contiguous commit range, not a sole-diff snapshot:** focus text does **not** scope the review (the companion reviews the whole target diff), and a change's edits span commits and rounds. So: base **B** = the **parent of the change's first commit**; require a **clean working tree**; **checkpoint-commit each round's accepted fixes**; run `adversarial-review --base B` each round, so `merge-base(B, HEAD)..HEAD` is always **the whole change and nothing else**. **Assert before every Pass-B launch:** (1) `git merge-base B HEAD` == `B`; (2) the tree is clean; (3) `git rev-list --merges B..HEAD` is empty; (4) the first commit in `B..HEAD` is the change-introduction commit; (5) **every commit in `B..HEAD` carries verifiable per-commit ownership for the named change** — a **validated `OpenSpec-Change: <name>` trailer on each range commit** (a *new convention this change introduces*) or an explicit **immutable commit-hash manifest** — **regardless of branch location**: a per-change branch/worktree MAY still be used for *isolation*, but is **not** accepted as ownership *proof* (a branch can hold interleaved/arbitrary commits), and path-based inference fails once implementation edits product files. **Fail closed** when any range commit lacks matching ownership metadata (or an unrelated commit is interleaved): do **not** review that range — build an **isolated review branch of only the change's commits** and review there.
- **Degrade — a 3-way classifier (`setup --json` individual fields; `status` has no `ready`):**
  1. **Capability absent** — the companion glob matches nothing, or `codex` is absent from PATH → **single-model degrade** (skip B, label the run single-model), **not** a hard failure. "Never installed" and "corrupted cache missing the companion" cannot be distinguished, so absent-companion **defaults to degrade**.
  2. **Present but broken** — the companion resolves but a **staged probe** fails: `codex --version`, `codex app-server --help`, or `setup --json` (each under a timeout) exits nonzero, times out, or emits malformed JSON → **HARD-FAIL, surfaced** — never a silent skip.
  3. **Auth absent, strictly identified** — skip Pass B **only** when **all** of `node.available===true && codex.available===true && auth.loggedIn===false && auth.source==="app-server" && auth.requiresOpenaiAuth===true` hold → label the run **single-model**. A null/absent `auth.requiresOpenaiAuth` is **INDETERMINATE → HARD-FAIL** (surface), not a skip — an app-server connect failure returns the **same** `loggedIn:false` shape as a genuine logout (see Context). **Honest cost:** the strict predicate **conservatively rejects some genuine logged-out states**; full unavailable-vs-broken correctness is **not achievable** in the installed plugin version (R4).
- **User-initiated per run:** the direct Bash call bypasses `disable-model-invocation`, so `/xtty:cross-review` is human-launched only — satisfying the **receipt-gated blocking pre-archive gate task** (D7), authorized per *run*, not per paid call (D4).

### D6 — Critic code-accuracy pass (Pass 4) — honest scope, axis reconciled
Extract claims about **existing** symbols (`` `Type.field` ``, `` `File.swift` ``, `"mirrors `X`"`) and grep source: an **existing** symbol absent/contradicted ⇒ BLOCKER; fuzzy/unlocatable ⇒ REVIEW. It **does not** catch a misplaced *new* field (R5 exempts to-be-created code — exactly what blinds it to the motivating `XttyConfigSet` bug), so that ownership class stays a **cross-model** catch. **Axis reconciliation:** Pass 4 has the critic read product source, which narrows the "critic = conformance, never reads source" split the premise leans on; this is defensible because it fact-checks a *stated existing-symbol claim* (a bounded factual check: "does the design's claim match the code?"), **not** open-ended code soundness ("is the approach right?") — the AGENTS.md two-axes framing SHALL state this explicitly so it stays honest. **Second honest bound: Pass 4 is in-repo-only** — it fact-checks claims against *this repository's* source, so it is **blind to external-dependency claims** (e.g. the Codex plugin internals this very change leans on); it would **not** have caught this change's own plugin-fact errors, and that class stays a cross-model / source-tracing catch. Bump `Definition: v4` and repair the launcher stamp **v1 → v4**.

### D7 — Mechanical gate; cross-review is a receipt-gated blocking pre-archive task, not an auto-firing marker
Scoped **mechanically** to changes touching **product code, a spec delta beyond docs/tooling, or the review/verification/CI tooling itself** (this last clause is load-bearing: this session proved a pure-tooling change benefits, so "product code only" would wrongly exclude it). Purely mechanical changes (docs/trackers/renames) stay single-agent-critic. **Honest framing:** this is *most substantive changes*, not a rare minority ("has a `design.md`" is ~100% and was never a gate); cost is bounded by running **once** and by degrade. **There is no auto-firing `⟶ xtty-cross-review` change-tail marker** — `/opsx:apply`'s point-of-tick grammar knows only *delegate-to-subagent* or *run-inline*, and a paid command that must **not** fire when its task is reached is neither. But a step placed **outside** the point-of-tick gets silently skipped — the repo's own measured failure class (the `fix-osc7` archive improvised past a rule that lived only in prose), and exactly what the earlier "separate human step outside the apply-loop tail" shape would reintroduce: `/opsx:apply` could tick the tail on the critic's return alone and archive with the cross-review never run. So the gate is expressed **at the point-of-tick as a receipt precondition** instead: (1) an in-scope change's tail carries a **distinct blocking cross-review gate task** (separate from the `⟶ xtty-openspec-critic` critic task) — the human runs `/xtty:cross-review <change>`, the run **persists the durable receipt** (`openspec/changes/<name>/cross-review-receipt.md`: verdict + adjudicated ledger + coverage label, per D4), and the task is **not ticked until that receipt exists** — a **human-attestation gate**, not a delegation and not prose-only guidance; (2) the **archive task verifies the receipt exists** for an in-scope change and **fails closed** (refuses to archive) when it is absent — so even if a round's tick slips, the archive precondition catches it (R10). This keeps the spend user-initiated (reaching the task fires nothing; only the human launch does) while keeping the gate inside the point-of-tick where the apply loop actually looks.

### Verification approach (by-effect + adversarial-env, non-vacuous)
Dev-workflow tooling. The riskiest claims (portable resolution, the 3-way degrade classifier, the commit-range substrate) manifest only in a *different* environment / after a version bump, so verification MUST exercise them adversarially **against the real `setup` probe** (not `status`, or the test passes vacuously): (a) **strict auth-absence** — all five predicate fields hold (`node.available && codex.available`, `auth.loggedIn==false`, `auth.source=="app-server"`, `auth.requiresOpenaiAuth===true`) → skip labeled single-model; (b) **capability absent** — move the companion out of the glob path (and/or strip `codex` from PATH) → **single-model degrade, not a hard failure** (fresh-machine semantics); (c) **present but broken** — stub a staged probe to exit nonzero / hang past the timeout / emit malformed JSON → **hard error surfaced**; (d) **indeterminate** — a `setup` payload lacking `auth.requiresOpenaiAuth` → **hard-fail**, not skip; (e) **non-vacuous semver resolution** — create a throwaway second version dir (or unit-test the resolver on a synthetic version list) so the `1.0.10 > 1.0.6` numeric ordering is actually proven, not assumed; (f) the commit-range assertions hold/decline correctly with several changes open, with an unrelated commit interleaved (→ isolated review branch), and with a range commit lacking ownership metadata (→ fail closed, even on a per-change branch); (g) **the receipt gate**: a completed run persists `cross-review-receipt.md` (verdict + adjudicated ledger), and the archive precondition **refuses** an in-scope change lacking one. No `verification-harness` delta.

## Risks / Trade-offs

- **R1 — Non-termination/thrash.** → gate on *unresolved* findings; dismiss-with-rationale legal; bounded N=2 + escalation.
- **R2 — Correlated model errors / consensus ≠ truth.** → consensus is a heuristic confidence signal (D3); the human sees every dismissal (D4).
- **R3 — Proportionality (accepted trade-off, recorded).** The orchestrator + loop + always-on gate is heavyweight machinery justified from **n=1** (one exemplar), and in the common **degrade** case A + C collapse to two *same-family* Opus passes = **no cross-model coverage at ~3× cost** while the gate requires the run. Round-2 Pass C flagged this against the anti-speculative-machinery refutation. **Decision (human, fix-forward):** proceed at full scope. **Mitigation:** a *known* Codex-absent context (CI/headless) SHOULD prefer the single-agent critic rather than pay 3× for A+C-same-family — the gate defers to critic there — and the proportionality is revisited after a few real runs (Open Questions).
- **R4 — Unavailable vs broken.** → **the** central fix (D5): a **3-way classifier** — capability-absent (no companion/`codex`) **degrades**, present-but-broken (staged-probe failure) **hard-fails**, and auth-absence skips **only** on the strict all-fields predicate (`node.available && codex.available && auth.loggedIn===false && auth.source==="app-server" && auth.requiresOpenaiAuth===true`); a null/absent `requiresOpenaiAuth` is indeterminate → hard-fail. **Honest limitation:** the plugin normalizes an app-server connect failure and a genuine logout into the same `loggedIn:false` shape and exposes no probe-success field, so the strict predicate **conservatively rejects some genuine logged-out states** — full correctness is not achievable in the installed plugin version; we accept surfacing-too-often over letting a broken integration masquerade as a clean degrade.
- **R5 — Code-accuracy false positives / narrow value.** → existing-symbol scope; new symbols exempt (⇒ REVIEW). This exemption is *why* Pass 4 can't catch the motivating bug (D6) — stated, not hidden.
- **R6 — Isolating one of several changes, across commits and rounds.** → the **commit-range substrate** (D5): base **B** = parent of the change's first commit, clean tree, checkpoint-commits per round, `--base B` every round, and the five pre-launch assertions — with **verifiable per-commit ownership** enforced on every range commit (a validated **`OpenSpec-Change: <name>` trailer** or an explicit immutable commit-hash manifest, **regardless of branch location** — a per-change branch/worktree isolates but does **not** prove ownership, since a branch can hold interleaved/arbitrary commits), **failing closed** when any range commit lacks matching ownership metadata; path-based inference fails once implementation edits product files, and an interleaved unrelated commit forces an isolated review branch of only the change's commits. Focus text is not scoping.
- **R7 — Convergence self-adjudicated.** → surface the full ledger + all dismissals every converged run (D4).
- **R8 — Async control-flow.** → background-B, run-A+C, await-B, merge (D3).
- **R9 — Self-dogfood circular under delivery-lag.** The change-tail dogfood (the group-4 cross-review gate task) runs against the v4 critic authored in the same effort, but agent-definition edits reach spawns with unpredictable lag → Pass A may be served the **stale v3** critic, silently missing the new code-accuracy pass. → **run the dogfood in a fresh session after v4 is committed**, or gate it on an explicit `Definition: v4` delivery check.
- **R10 — The apply loop could tick the blocking gate task prematurely.** The blocking cross-review task is still a checkbox; an over-eager `/opsx:apply` round could tick it without the receipt existing — the honest residual of any point-of-tick gate. → the tick is *attestation*; the **receipt is the enforcement**: the archive task's **fail-closed receipt precondition** (D7) catches a slipped tick before any spec delta merges — archive refuses when `cross-review-receipt.md` is absent for an in-scope change. Residually, that precondition is itself a procedure the session must honor (it joins the archive-ritual pre-tick self-check); a session that ignores both the gate task's blocking condition *and* the archive precondition operates outside the workflow's contract — accepted and stated, not hidden.

## Migration Plan

Additive tooling; rollback = revert. The single-agent `/xtty:review` is unchanged (code-accuracy is a strict addition). Codex is a pre-existing dependency.
