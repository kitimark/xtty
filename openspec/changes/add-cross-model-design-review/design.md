## Context

The `coherence-review` capability delegates full coherence review to the committed Opus `xtty-openspec-critic` agent (conformance: rulebook + disk-drift; never reads product source). This change adds a **second, differently-modeled soundness axis** and a **human gate** on top of it.

**This proposal was re-architected after six rounds of its own cross-model review.** The original shape — a model-operated convergence gate that wrote a "converged" receipt which archive then checked — was refuted every round: a receipt/verdict/coverage-label is **model-authored**, so a mechanical check of it still trusts the model, and a model could dismiss every finding and self-certify (it also could not dogfood its own commit-trailer ownership rule on its already-landed history). The irreducible finding, dogfooded live via a Fable-5 + `gpt-5.6-sol` fan-out: **the human is the gate, not the model.** The design therefore splits into two layers with a hard rule between them — **the worker may be arbitrarily helpful but carries zero authority; the gate is authority-complete but has near-zero machinery and reads no model-authored artifact.** Every mechanism the prior iteration had that gave a model artifact gate force is deleted.

Fact-checked properties of the installed Codex plugin (`~/.claude/plugins/cache/openai-codex/codex/<v>/`), used to *run and report* Pass B, never to gate:
- `setup --json` emits `node.available` / `codex.available` / `auth.loggedIn` / `auth.source` / `auth.requiresOpenaiAuth`; it connects to the app-server and **normalizes a connect failure and a genuine logout into the same `loggedIn:false` shape** (so availability is best-effort, which is fine — an unavailable reviewer is a *reported skip*, not a gate decision). `status` has **no `ready` field**.
- The review **input is the full diff** of the resolved git target; **focus text is prompt guidance, not a path filter**.
- The companion's `--background` flag is a **no-op for `adversarial-review`** (always foreground); backgrounding must live in the harness's Bash `run_in_background`.
- The `review-output` schema requires per-finding `severity/title/body/file/line_start/line_end/confidence/recommendation` (**no `line`**, `additionalProperties:false`); it ships under `schemas/`.
- Invocation is via a version-pinned script path; `${CLAUDE_PLUGIN_ROOT}` is unset in a project command; `adversarial-review` accepts `--model` but exposes **no per-call effort flag**; the command is `disable-model-invocation: true`.

Binding refutations: **`run_in_background` strands subagents** (so the worker runs in the main loop, never a subagent); **don't pre-build speculative dev-workflow machinery**; **agent-definition edits reach spawns with unpredictable lag**.

## Goals / Non-Goals

**Goals:** a committed, repeatable cross-model review **worker** (conformance ∥ two-family soundness) with a union-with-heuristic-consensus **advisory** ledger and a bounded fix→re-review loop; a **human-attested, fail-closed archive gate** that reads no model-authored artifact; a critic hardened to fact-check *existing-code* claims and to require the gate task on in-scope changes.

**Non-Goals:** not per-edit; not a new standing agent (Pass C inline); not literal model agreement; **not a model-authored gate of any kind** (no receipt, no converged-verdict-as-eligibility, no coverage-label-as-gate); not commit-trailer ownership; not mandatory signing; no product-code / `verification-harness` change.

## Decisions

### D1 — New `cross-model-review` capability + a `coherence-review` MODIFY
The worker + inline fix-loop is a new capability (the loop *edits* artifacts; `coherence-review` is observe-only). The code-accuracy pass **and** the gate-task-presence check MODIFY the critic.

### D2 — Worker runs in the main loop, not a subagent
The loop drives a detached Codex call and edits artifacts between rounds; a subagent owning Codex hits the strand refutation. `/xtty:cross-review` is a main-loop protocol; the passes stay observe-only.

### D3 — Tri-pass on the real schema; consensus heuristic; the ledger is advisory
- **Pass A** — Opus critic (conformance, + code-accuracy D6). **Pass B** — Codex/GPT soundness. **Pass C** — inline Opus soundness, **emitting the real `review-output` schema** so B and C are comparable.
- **Consensus is a heuristic confidence signal, not a mechanical join** (two differently-modeled reviewers diverge on title, file attribution, line ranges — same-finding matching is semantic).
- **The merged ledger is advisory in its entirety.** It MAY be persisted as a **gate-inert** `cross-review-ledger.md` for audit, but nothing downstream reads it mechanically. Its header names the reviewed range (base, HEAD, file list) and the effective model of each soundness pass — plus its effort **where determinable** (D9: Pass B exposes no per-call effort control).
- **Async-join:** launch B in the background **via the harness's Bash `run_in_background`** (the companion's `--background` is a no-op for `adversarial-review`); run A + C as subagents; **await B's re-invoke before merging**. Safe because the **main loop** owns the call.

### D4 — Bounded iteration is worker behavior, not archive eligibility
A round runs A∥B∥C; the caller adjudicates each finding **fix** or **dismiss-with-recorded-rationale**, applies fixes (checkpoint-committed), re-runs. Bound **N = 2 rounds**; on the bound, escalate the residual. **A single launch authorizes the whole bounded run** (owned honestly: user-initiated per *run*, not per paid call). The worker SHALL surface the **complete** union ledger — every finding with its resolution, **every dismissal with its recorded rationale**, and any residual escalated at the round bound — on **every** run, never a filtered subset: the human gate (D7) is the sole acceptance authority and rests **entirely** on reading this ledger, so completeness is load-bearing, not a courtesy. Crucially: **"converged" carries no gate force, and a dismissal is a *proposal*, not an accepted state.** There is **no receipt** and no reviewed-state binding produced by the worker — archive eligibility lives entirely in the human gate (D7), computed from git, not from anything the worker wrote.

### D5 — Codex mechanics: portable resolution, deterministic range, detectable non-gating skip
- **Locate:** glob `~/.claude/plugins/cache/openai-codex/codex/*/scripts/codex-companion.mjs`, pick the highest version **numerically** (`1.0.10 > 1.0.6`). No match (or `codex` absent from PATH) is a **reported skip**, not a failure.
- **Review substrate — a deterministic best-effort range, no ownership metadata:** focus text does not scope the review, so base **B** = the **parent of the commit that added the change's `proposal.md`** (a purely positional git rule); require a clean tree; checkpoint-commit each round; run `adversarial-review --base B`. The range tooling SHALL **assert, fail-closed, that the `proposal.md`-introducing commit is the *first* commit touching `openspec/changes/<name>/`** — an earlier change-dir commit means the positional rule would silently omit range history, so the tool refuses with a named error instead of proceeding. Known limitation, stated honestly: work committed *before* `proposal.md` **outside** the change directory (e.g. product code landed pre-proposal) is invisible to the range; the human catches it via the header's **named file list** (a reviewed scope that omits an obviously-touched file is the tell). The range is also self-healing forward: the attested digest binds the **whole `B..HEAD` net diff**, so a concurrent commit landing after attestation changes the recomputed digest and **forces re-attestation** — fail-*closed* friction, not a hole. **The worker names `B`, HEAD, and the reviewed file list in the ledger header** so the human sees exactly what was reviewed. This is *best-effort* isolation: it does **not** prove every range commit belongs to the change (the deleted `OpenSpec-Change:` trailer machinery tried to and could not even dogfood itself). Transparency (a named range a human reads) replaces a trusted-metadata assertion chain — appropriate because the worker has no authority anyway.
- **Mechanical scope classifier (feeds D7's applicability; not a model judgment):** a **committed deterministic script** (`scripts/`) classifies the change in/out of the archive gate's scope from the range's **changed paths** (`git diff --name-only B..HEAD`) against a **fixed allowlist of documentation/tracker surfaces** (the change's own `openspec/changes/<name>/` prose artifacts, `research/`, the tracker docs, the advisory ledger — the committed script is the authority on the exact patterns). **Any path outside the allowlist ⇒ in scope; an unrecognized or ambiguous path ⇒ in scope (fail-closed).** The allowlist deliberately errs narrow: over-inclusion costs one review, under-inclusion is a gate bypass. This replaces the earlier semantic in-scope call: it makes an *accidental* out-of-scope slip mechanically detectable and removes an ambiguity-judgment surface from the scoping decision (ambiguous ⇒ in-scope) — an accident tripwire per D10, **not** a guarantee that a repo-controlling session cannot exempt a change (that affirmative act is the R3 residual).
- **Availability, reported not classified:** read `setup --json` fields only to decide *run Pass B or skip-and-report*. Resolvable companion + `codex.available` + `auth.loggedIn` → run. Otherwise skip and state why in the header. A present-but-broken integration MAY be surfaced as a header warning, but no availability state gates archive — the prior iteration's 3-way hard-fail/auto-satisfy classifier is deleted.
- **User-initiated per run:** the direct Bash call bypasses `disable-model-invocation`, so `/xtty:cross-review` is human-launched only.

### D6 — Critic gains a code-accuracy pass (Pass 4) and a gate-task-presence check
- **Pass 4 (code-accuracy), honest scope unchanged:** extract claims about **existing** symbols and grep source — existing symbol absent/contradicted ⇒ BLOCKER; fuzzy ⇒ REVIEW. It does **not** catch a misplaced *new* field (that stays a cross-model catch), and is **in-repo-only** (blind to external-dependency claims, e.g. the Codex plugin internals). The AGENTS.md two-axes framing states this so it stays honest.
- **Gate-task-presence check (new, REVIEW-severity):** for an **in-scope** change, verify the `tasks.md` tail carries the blocking human-attestation cross-review task with its model-STOP/HUMAN-ONLY wording; REVIEW (never BLOCKER — the critic's in-scope call is semantic) when absent. This is the mechanism that makes the gate-task convention reach `/opsx:propose` instead of living only in AGENTS.md prose (the repo's measured "a rule that lives only in AGENTS.md doesn't reach the loop" failure).
- **Two scope determinations, deliberately different strengths:** the archive gate's *applicability* is the **mechanical path classifier** (D5/D7 — deterministic, fail-closed, never a judgment); the critic's gate-task-presence nudge uses a *semantic* in-scope reading at **REVIEW** severity — a propose-time authoring affordance, not the gate. They can disagree; the mechanical call is the one with force. And Pass 4 rides along in this change for its independent value — it is **not** aimed at the motivating exemplar's misplaced-*new*-field class (that stays a cross-model catch).
- Bump `Definition: v4`; repair the launcher stamp **v1 → v4**.

### D7 — The gate is a human tick at the point-of-tick; archive fails closed (the core decision)
Archive eligibility rests on an **explicit human attestation**, never a model artifact. **Applicability is mechanical:** step 0 of the hand-authored `⟶ archive-ritual` first runs the committed **scope classifier** (D5) over the change's changed paths to decide whether the precondition applies — any path outside the docs/tracker allowlist, or an unrecognized/ambiguous path, ⇒ in scope; never a model judgment. An in-scope change's tail carries **one blocking human-attestation task**, after `⟶ xtty-openspec-critic` and before `⟶ archive-ritual`. It is **HUMAN-ONLY**: the model MUST STOP — it may not tick the task and may not derive/compute/fill the attested value. The human runs `/xtty:cross-review`, reads the complete ledger (D4), runs the committed digest tool (D8), and ticks the task **recording the reviewed-state digest on a delimited attestation line** — a stable textual marker precisely bounding the attested surface inside `tasks.md` (deliberately **not** a separate per-change attestation file, which would re-grow a receipt-shaped artifact), so the integrity checks can identify exactly what to exclude and exactly what the attestation act may touch. The archive precondition **fails closed** unless all four hold: (1) the attestation exists and is well-formed (grep for the delimiter); (2) the reviewed-state digest **recomputes** and string-equals the attested value; (3) the tree/index is clean (the digest tool's own dirty-refusal); (4) **exempt-by-act** — the delimited attestation line appears **exactly once**, under the committed template's fixed grammar, and is **byte-identical from its introducing commit through archive**; that introducing commit's `tasks.md` hunk is confined to the **delimited attestation line plus checkbox-state ticks** — no reviewed artifact, no gate implementation; and every *later* commit touches only the **remaining** bookkeeping surfaces (checkbox ticks, the advisory ledger) — any later addition, deletion, or modification of the attestation line **invalidates the attestation** and requires a fresh review + attestation cycle. These checks catch *accidental* post-review drift — a reviewed artifact edited after attestation, a rewritten attestation line, a checker edit riding the attestation commit — and keep the attested surface legible; per D10 they are accident tripwires, not adversarial guarantees (a repo-controlling model evading them is the R3 residual). The check runs the digest/scope tooling **from the reviewed-base version** where one exists (D8). Inputs: the human's line, a git-computed digest from committed deterministic tooling, git ground truth — **no model-authored artifact**.

**Why this is sound where six rounds were not.** It separates two failure classes. The refuted class (round-6 #3): a model **passes the gate by doing its assigned job** — dismiss, converge, write receipt — a design flaw, because correct behavior defeats the guarantee. This design **deletes that class entirely** (no model artifact has gate force). The residual class it owns: a model commits an **affirmative forbidden act** — forging a human tick + digest line — which is the **same trust class the repo already accepts for every committed procedure** (a session that ignores `⟶ archive-ritual` is already outside the workflow's contract). A design that states its trust boundary honestly is sound; one that overclaims is not.

### D8 — The deterministic digest tool, exempt-by-act staleness, and optional-not-default signing
- **Digest tool** (`scripts/`, ~10 lines, committed, deterministic): refuses on a dirty tree/index; prints a digest of `git diff B..HEAD` **excluding exactly the bookkeeping surfaces** — the advisory ledger and the tick/attestation surface in `tasks.md` (the delimited attestation line + checkbox-state ticks) — so recording the attestation cannot self-invalidate the digest. `B` per D5 (including its first-commit fail-closed assertion).
- **Exempt-by-act staleness** closes the hole `gpt-5.6-sol` found that all three fan-out candidates left open: a by-*path* exclusion of the attestation surface lets the attestation record be **rewritten** post-attestation without the digest changing. So archive additionally verifies (check 4) that the attestation line appears **exactly once** and is **byte-identical from its introducing commit through archive** (any later addition/deletion/modification of it invalidates the attestation → fresh review + attestation), that the introducing commit's `tasks.md` hunk is confined to the delimited attestation line + checkbox ticks — touching **no reviewed artifact and no gate implementation** — and that every later commit touches only the remaining bookkeeping surfaces: content-unchanged (digest) *and* attestation authentic, singular, and unrewritten (exempt-by-act). A commit that records the attestation **and**, in the same act, edits the digest/scope tooling or any reviewed artifact fails closed.
- **Run the gate tooling from the reviewed base (anti-self-weakening), with an honest bootstrap boundary:** the archive step runs the digest and scope-classifier scripts **as of the reviewed-base version** (`git show B:scripts/…` semantics) wherever a prior committed version exists — **including when the change under archive *modifies* that tooling: the reviewed-base version exists there and is precisely the anchor that keeps a checker edit from validating itself** — so a checker edit bundled alongside the content it would weaken is caught rather than silently self-validating (an accident tripwire per D10, not an adversarial guarantee — a repo-controlling model rewriting history around it is the R3 residual). Only a change that *introduces* the tool — this change — has **no prior version to run from**; the trust anchor there is **human code review of the committed scripts**, an accepted and stated boundary, **not** a mechanically-closed one (the same trust class as R7 — do not imply otherwise).
- **Optional strong form, explicitly not default:** `git commit -S` over the attestation + `git verify-commit` against an allowlisted key, verified **when present**. Rationale for optional-not-default: signing converts the barrier from an **instruction** ("HUMAN-ONLY, don't fill the line") to a **capability** ("the model cannot produce the human's signature") — but it only bites at an **out-of-band boundary** (CI/branch-protection or a human-run archive), because an in-loop model runs `verify-commit` itself. Defaulting it pays thinness + dogfood cost for closure it does not deliver in-loop, against the repo's $0/no-ceremony ethos.
- **Test-precision vs. the claim (the dogfood test):** claim = *"archive fails closed absent a fresh human attestation of the current reviewed-state digest"*; the claim lives in the **archive ritual's step-0 check**; the by-effect driver — a **real archive attempt on this very change** (D7's dogfood, task 5.2/5.3) — reaches that layer directly, and a stale/rewritten attestation must be shown failing closed. No synthetic/read-back check substitutes.

### D9 — Model-family diversity pin: Pass B = GPT (`gpt-5.6-sol` / `xhigh`), Passes A/C = Opus; reported, not gated
The spec's diversity requirement is mechanism-neutral (two soundness passes on **distinct families**, at an effort suited to deep adversarial review); the **concrete pin lives here** so it survives model drift. **Pass B = `gpt-5.6-sol`** (the GPT-family model the local codex CLI is configured with) at **`xhigh`** effort (a lower effort is defensible but not one so shallow it misses source-traced issues — the worked exemplar's config-ownership catch required tracing a claim into source). **Passes A/C = Opus.** The worker pins the **model** explicitly at invocation (`--model gpt-5.6-sol`); the **effort is not per-call-pinnable** — `adversarial-review` exposes **no per-call effort flag** (verified against the installed companion), so the `xhigh` effort is governed by the codex CLI's own configuration, an *expectation stated here*, not an invocation pin. The worker **records the effective model of each soundness pass — and its effort where determinable (Pass C's is invocation-controlled; Pass B's is reported from the codex config when readable, else marked undetermined) — in the ledger header**, so a human can see whether the run was genuinely cross-family. Family diversity — the load-bearing part — is invocation-pinned and intact. A divergent local config yields an **honestly-labeled header a human reads**, not a blocked gate (the prior iteration's coverage-label-as-gate audit is deleted). A skipped Pass B leaves A + C same-family → the header says **single-model**.

### D10 — The mechanical checks are accident tripwires, not adversarial guarantees (the thin-claim boundary)
The gate's mechanical checks — the reviewed-state digest, the clean-tree requirement, the exempt-by-act rule, the scope classifier, and the named review range — are **accident tripwires and human-legibility aids**: they catch *accidental* post-review drift (an edit after attestation, a dirty tree, a change slipping past scope) and make the reviewed range legible so the human *can* judge its adequacy. They are **not** adversarial-integrity guarantees against a model that controls the repository. A model running the apply loop controls git history — it can rewrite the range base, rename directories, or forge the tick — so **no** mechanical git-provenance check is airtight against it; every such 'bypass' reduces to the **R3 residual** (a repo-controlling model performing an affirmative forbidden act, the same trust class the repo already accepts for every committed procedure). Adversarial resistance lives in exactly two places: **the human reading the complete ledger** (with the named range + file list surfaced so range-adequacy is a human judgment) and the **R3 boundary**. This is load-bearing: a design that *claims* mechanical airtightness invites an unbounded regress of git-manipulation bypasses (proven empirically — see the tar-pit note in Open Questions); a design that scopes the mechanical checks to accident-catching + human-legibility, and routes all adversarial resistance through the human + R3, is thin, honest, and terminating.

## Risks / Trade-offs

- **R1 — Non-termination/thrash.** → bounded N=2 + escalation; and iteration is worker behavior with no gate pressure to converge.
- **R2 — Correlated model errors / consensus ≠ truth.** → consensus is a heuristic signal; the human sees every dismissal on every run (D4).
- **R3 — The model physically writes the tick (the irreducible residual).** In a model-driven apply loop the model writes `tasks.md` and *could*, as an affirmative **forbidden** act, forge the tick + digest line; no in-repo check the same model runs closes this mechanically (`gpt-5.6-sol` is correct on this). Under the given invariant this is the **accepted honest boundary** — an instruction-barrier, a **different failure class** from the refuted self-certification (D7). The winner **deletes the self-certification class** and owns only this residual, which is the **same class the repo already accepts** for every committed procedure. Mitigations: the point-of-tick HUMAN-ONLY marker; the human reviewing the tick and archive commits; and the optional signing strong form (D8) for anyone who needs mechanical, not procedural, forgery-resistance.
- **R4 — Full mechanical closure needs an out-of-band boundary the winner does not mandate.** Signing only bites where verification runs somewhere the model cannot skip (CI/branch-protection or a human-run archive). In a single-machine model-only loop with no signing and no CI gate, nothing is model-proof — stated, with the CI/signing knob named (D8), not hidden.
- **R5 — The human can rubber-stamp.** No design forces a careful read; the winner guarantees only that the information for one (per-pass header, coverage, consensus flags, every dismissal + rationale) is **complete, surfaced, and truthful**, and that nothing pretends to have done the reading.
- **R6 — Code-accuracy false positives / narrow value.** → existing-symbol scope; new symbols exempt (⇒ REVIEW). This exemption is *why* Pass 4 can't catch the motivating bug (D6) — stated, not hidden.
- **R7 — The digest tool and archive check are trusted repo code.** → the same trust already extended to `git`/`make`/the `openspec` CLI (committed, human-reviewable, deterministic) — categorically different from the runtime model judgment the invariant forbids trusting; a mis-edited script is a **code-review** concern, not a gate-design one.
- **R8 — Exempt-by-act is the one place the gate leans beyond the digest.** → the dogfood (task 5.2/5.3) must exercise it: a stale or rewritten attestation must fail closed.
- **R9 — Self-dogfood circular under delivery-lag.** Pass A on the change's own tail may be served the **stale v3** critic. → run the dogfood in a fresh session after v4 is committed, or gate on an explicit `Definition: v4` delivery check.
- **R10 — The gate has been reasoned-about, not yet exercised.** This change's own tail (the human runs `/xtty:cross-review` on `add-cross-model-design-review` and attests) is the **first real attestation and the acceptance test**; a green archive that provably fails closed on an absent or stale attestation is the by-effect proof, and until it runs the design carries the usual unexercised-mechanism risk.

## Migration Plan

Additive tooling; rollback = revert. The single-agent `/xtty:review` is unchanged (Pass 4 + the gate-task check are strict additions). Codex is a pre-existing dependency.

The advisory pass raised **no beyond-the-four residuals**; its one encoding correction — the reviewed-base clause originally read *"introduces or modifies"*, false for the **modifies** arm (a modification runs from its existing base version, which is exactly the anti-self-weakening anchor) — was **applied in-round** to the spec, so the boundary is now "introduces-only" across spec, design, tasks, and proposal.

### The mechanical-airtightness tar pit (empirical, this session)
A convergence experiment ran this proposal's own loop on the proposal (Claude fixing, gpt-5.6-sol verifying, until agreement); over four rounds it did NOT converge — each round's mechanical hardening of review-base/range provenance opened the next git-manipulation narrowing (pre-attestation rewrite -> re-record deadlock -> ownership-vs-completeness -> directory-rename rename-blindness), the spec bloated 45%, round 4 regressed a round-1 guarantee. Finding: mechanizing provenance integrity against a repo-controlling model is non-terminating (the closable-bypass set for git history is effectively unbounded; every member reduces to the R3 residual) — hence D10 (thin the claim). Second-order finding: adversarial spec-review of dev tooling has a hard diminishing-returns cliff — a dev tool is validated by building and using it (task 5.2), not by reviewing its spec forever. Full record: research/03-analysis/cross-model-review-tar-pit-*.md.
