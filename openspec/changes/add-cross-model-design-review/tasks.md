## 3. Human-gate plumbing (cross-model-review)

- [ ] 3.1 Author the **committed deterministic reviewed-state digest tool** under `scripts/` (design D8): given a change name, resolve base **B** from the change's **recorded review base** (`openspec/changes/<name>/review-base` — **refusing with a named error** when the record is absent, unresolvable, or not an ancestor of HEAD, design D5), **refuse on a dirty tree/index**, and print a digest of `git diff B..HEAD` **excluding exactly** the bookkeeping surfaces — the advisory ledger and the `tasks.md` attestation/tick surface (the **delimited attestation line** + checkbox-state ticks); the `review-base` record itself is **not** a bookkeeping surface — so recording the attestation cannot self-invalidate the digest while a base rewrite always does. Deterministic; trust class of `git`/`openspec`.
- [ ] 3.2 Author the **committed mechanical scope classifier** under `scripts/` (design D5/D7): given a change name, compute the range's changed paths over the **same recorded review base** the review and digest use (`git diff --name-only B..HEAD`) and classify against a **fixed allowlist of documentation/tracker surfaces** — **any path outside the allowlist ⇒ in scope; an unrecognized or ambiguous path ⇒ in scope (fail-closed); an absent, unresolvable, or non-ancestor recorded base ⇒ in scope (fail-closed)** — never classify a change out of scope on a range that could not be resolved. Deterministic, path-based, **no model judgment**; the script is the authority on the allowlist patterns.
- [ ] 3.3 Establish the **review-base recording convention** (design D5): at change creation — **before implementation work begins** — write the current HEAD's full sha to `openspec/changes/<name>/review-base` (one line) and commit it with the proposal; document the one-liner in the AGENTS.md gate convention (§3.5). **Record this change's own review base retroactively** (it predates the tooling): the parent of its `proposal.md`-introducing commit, chosen and verified by a human against `git log` — acceptable here under D8's bootstrap boundary, since this tooling-introducing change is anchored by human code review anyway.
- [ ] 3.4 Add to the hand-authored **`⟶ archive-ritual`** procedure in `AGENTS.md` a **step 0** that first **invokes the committed scope classifier (§3.2) to decide applicability** over the recorded-base range — never a semantic call — and, for an in-scope change, **FAILS CLOSED** unless all four hold (design D7/D8): (1) the human attestation exists and is well-formed on its **delimited attestation line**; (2) the reviewed-state digest **recomputes** and equals the attested value; (3) the tree/index is clean; (4) **exempt-by-act** — the attestation line appears **exactly once** and stays **byte-identical from its introducing commit through archive** (any later add/delete/modify of it invalidates the attestation → fresh review + attestation); the introducing commit's `tasks.md` hunk is confined to the **delimited line + checkbox ticks**, and every later commit touches only the remaining bookkeeping surfaces (no reviewed artifact, no gate implementation). The step runs the digest/scope tooling **from the reviewed-base version wherever a prior committed version exists — including when the change under archive *modifies* that tooling** (only a tooling-*introducing* change like this one has none — the stated anchor there is human code review of the scripts, design D8). The check reads **no model-authored artifact** (inputs: the human's line, the git-computed digest, git ground truth). Note the **optional-not-default** signing strong form (`verify-commit` when the attestation is signed).
- [ ] 3.5 Document the **gate convention** in `AGENTS.md`: the **review-base recording rule** (§3.3 — recorded at change creation before implementation; resolved identically by review, digest, and scope; fail-closed when absent, unresolvable, or not an ancestor of HEAD); the **mechanical path-based scope classifier** (fixed docs/tracker allowlist, computed over the recorded-base range; outside ⇒ in scope; ambiguous ⇒ in scope, fail-closed; purely-allowlisted docs/tracker/rename changes stay critic-only); the **human-attestation task template** — placed after `⟶ xtty-openspec-critic` and before `⟶ archive-ritual`, **HUMAN-ONLY / model-MUST-STOP**, ticked only by a direct human act recording the reviewed-state digest on the **delimited attestation line**, **no** auto-firing `⟶ xtty-cross-review` marker; and the archive step-0 checks incl. the reviewed-base tooling rule + its bootstrap boundary (§3.4). Also add the **worker protocol** (passes, advisory ledger + header contract, **complete-ledger-every-run surfacing**, bounded rounds, one-launch spend, model-family diversity, detectable non-gating degradation) and the two-axes framing (conformance vs soundness; Pass 4 fact-checks *stated existing-symbol claims*, a bounded in-repo check, not open-ended code soundness).
- [ ] 3.6 Update `AGENTS.md`'s committed-tooling bullet + the agents/launchers table to list `/xtty:cross-review`, the digest tool, and the scope classifier, noting Pass C is inline (emitting the common schema), not a standing agent (anti-roster refutation).
- [ ] 3.7 Verify by inspection: `AGENTS.md` states the worker protocol (incl. complete-ledger-every-run), the review-base recording rule, the mechanical path-based scope classifier (over the recorded-base range) + pre-archive timing, the human-attestation gate convention (critic tail marker retained; the cross-review gate is its own HUMAN-ONLY blocking task with no auto-firing marker; the delimited-line digest tick), the archive step-0 fail-closed precondition (classifier-decided applicability; the four checks incl. exempt-by-act + the reviewed-base rule + its bootstrap boundary + optional signing), the model-family diversity rule (GPT-family Pass B pinned by `--model`, effort config-governed; Opus A/C; skipped B → single-model header), and the detectable non-gating degradation behavior.
- [ ] 3.8 Verify the gate's **bypass resistance by effect** (fail-closed drills, complementing 5.3's live archive test): (a) **scope bypass** — a change whose range touches a product/tooling path **cannot** be classified out of scope, and an unrecognized/ambiguous path classifies **in scope**; (b) **attestation-commit bundling / rewrite** — an attestation commit that also modifies the digest/scope tooling, or edits a reviewed artifact, **fails the archive precondition closed**, and a *later* commit that adds, deletes, or modifies the delimited attestation line **invalidates the attestation** (fail closed); (c) **pre-proposal base bypass (the Round-1 hole, closed)** — a product/tooling commit landing after the recorded base but before the `proposal.md` commit, touching **no change-dir path**, lies **inside** the range: it is reviewed, digested, and drives the classifier **in scope** (it can no longer silently become the base and vanish from review, digest, and scope alike); (d) **unresolvable base** — an absent, unresolvable, or non-ancestor `review-base` makes every consumer **refuse with a named error** (never a guessed or narrower range), the classifier classify **in scope**, and the digest uncomputable, so the archive precondition cannot pass; and (e) **base rewrite** — a post-attestation commit that modifies `review-base` **invalidates the attestation** (digest mismatch + exempt-by-act, fail closed).
