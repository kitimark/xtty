## 2. Cross-model review orchestrator (cross-model-review)

- [ ] 2.1 Author `.claude/commands/xtty/cross-review.md` as the **main-loop protocol**: given an in-scope change, launch **Pass B** (`codex-companion.mjs adversarial-review`) in the **background** (owned by the main loop, never a subagent — strand refutation), run **Pass A** (the Opus critic) and **Pass C** (an inline Opus soundness `Agent` call mirroring B's lens) as subagents, then **await Pass B's completion re-invoke before merging** (concurrent passes, barrier merge — design D3). State that `/xtty:cross-review` is **user-launched only** (the direct Bash call bypasses Codex's `disable-model-invocation` guardrail), and that **one launch authorizes the whole bounded run** (up to N rounds of paid Pass B) — a new review needs a new launch (design D4).
- [ ] 2.2 Specify **portable location + sole-diff scoping** for Pass B: resolve the companion by globbing `~/.claude/plugins/cache/openai-codex/codex/*/scripts/codex-companion.mjs`, picking the highest version by **semver/numeric** compare (not lexical — `1.0.10 > 1.0.6`), **fail loud** if none (`${CLAUDE_PLUGIN_ROOT}` is unset in a project command). Scope by **precondition, not focus text** (which does not restrict what Codex reviews): **assert the named change is the sole change in the reviewed diff** — sole dirty change, or sole HEAD commit — before launch, and decline to run Pass B repo-wide otherwise (design D5/R6).
- [ ] 2.3 Specify the **common-schema union-with-consensus ledger**: **Pass C emits Codex's real `review-output` JSON schema** (top-level `verdict/summary/findings/next_steps`; per-finding `severity/title/body/file/line_start/line_end/confidence/recommendation` — **no `line`**, `additionalProperties:false`); merge findings tagged by source; flag a finding raised by **both** B and C as a **heuristic** two-model consensus signal — the same-finding match is a semantic judgment, not a mechanical join (design D3).
- [ ] 2.4 Specify the **terminating convergence loop**: each round adjudicate every finding as fix | dismiss-with-recorded-rationale, apply fixes, re-review; converged = zero unresolved findings from any pass (not identical output); bound at **N = 2 rounds**, then escalate the residual. On **every converged run**, surface the **full ledger including all dismissals + rationales** to the human (not only at the bound), so convergence-by-dismissal is visible (design D4).
- [ ] 2.5 Specify the **detectable degrade path** on Codex's **`setup --json` individual fields** (`node.available`, `codex.available`, `auth.loggedIn`) — the assumed `status → ready` probe does **not** exist: **skip Pass B only** on a positively-identified **auth absence** (node+codex present, not logged in) → run A + C, **label the run single-model** (A + C are same-family → no cross-model coverage); a **missing binary, unresolved path, indeterminate/timed-out probe** (setup contacts the app-server), or spawn/module error → **surface hard as a misconfiguration**, never a silent skip (design D5/R4).
- [ ] 2.6 Confirm the command is committed (un-ignored) alongside the other `.claude/commands/xtty/` tooling (`.gitignore` allowlist covers it).
- [ ] 2.7 Verify by effect **and adversarial environment** (non-vacuous — against the real `setup` probe, not `status`): run `/xtty:cross-review` on a real in-scope change (tri-pass fires, ledger merges with a consensus flag, loop converges/escalates, full ledger surfaced); then **simulate degradation** — unset auth → `setup` shows `auth.loggedIn==false` → skip labeled single-model; **hide the `codex` binary** → `codex.available==false` → a **hard error surfaced, not a silent skip**; confirm semver-correct resolution independent of the installed version, and that the sole-diff precondition holds/declines correctly with several changes open.
