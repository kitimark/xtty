## 2. Cross-model review orchestrator (cross-model-review)

- [ ] 2.1 Author `.claude/commands/xtty/cross-review.md` as the **main-loop protocol**: given an in-scope change, launch **Pass B** (`codex-companion.mjs adversarial-review`) in the **background via the harness's Bash `run_in_background`** — the companion's own `--background` flag is a **no-op for `adversarial-review`** (it always runs foreground; only *task* subcommands branch on background) — owned by the main loop, never a subagent (the strand refutation applies to subagents); run **Pass A** (the Opus critic) and **Pass C** (an inline Opus soundness `Agent` call mirroring B's lens) as subagents, then **await Pass B's completion re-invoke before merging** (concurrent passes, barrier merge — design D3). State that `/xtty:cross-review` is **user-launched only** (the direct Bash call bypasses Codex's `disable-model-invocation` guardrail), and that **one launch authorizes the whole bounded run** (up to N rounds of paid Pass B) — a new review needs a new launch; spend is human-initiated **per run**, not per paid call (design D4).
- [ ] 2.2 Specify **portable location + the commit-range review substrate** for Pass B: resolve the companion by globbing `~/.claude/plugins/cache/openai-codex/codex/*/scripts/codex-companion.mjs`, picking the highest version by **semver/numeric** compare (not lexical — `1.0.10 > 1.0.6`); an absent companion is a **capability-absent degrade** per 2.5, not a fail-loud (`${CLAUDE_PLUGIN_ROOT}` is unset in a project command). Scope by **substrate, not focus text** (which does not restrict what Codex reviews): base **B** = the parent of the change's first commit; require a **clean working tree**; **checkpoint-commit each round's accepted fixes**; run `adversarial-review --base B` each round so `merge-base(B, HEAD)..HEAD` is always the whole change. **Assert before launch:** `git merge-base B HEAD` == `B`; the tree is clean; `git rev-list --merges B..HEAD` is empty; the first commit in `B..HEAD` is the change-introduction commit; and **every commit in `B..HEAD` carries verifiable per-commit ownership for the named change** — a **validated `OpenSpec-Change: <name>` trailer on each range commit** (the new convention this change introduces) or an explicit **immutable commit-hash manifest** — **regardless of branch location** (a per-change branch/worktree MAY be used for *isolation* but is **not** accepted as ownership *proof*: a branch can hold interleaved/arbitrary commits; path-based inference fails once implementation edits product files). **Fail closed** when any range commit lacks matching ownership metadata (or an unrelated commit is interleaved): decline and review an **isolated review branch of only the change's commits** (design D5/R6).
- [ ] 2.3 Specify the **common-schema union-with-consensus ledger**: **Pass C emits Codex's real `review-output` JSON schema** (top-level `verdict/summary/findings/next_steps`; per-finding `severity/title/body/file/line_start/line_end/confidence/recommendation` — **no `line`**, `additionalProperties:false`); merge findings tagged by source; flag a finding raised by **both** B and C as a **heuristic** two-model consensus signal — the same-finding match is a semantic judgment, not a mechanical join (design D3).
- [ ] 2.4 Specify the **terminating convergence loop**: each round adjudicate every finding as fix | dismiss-with-recorded-rationale, apply fixes, re-review; converged = zero unresolved findings from any pass (not identical output); bound at **N = 2 rounds**, then escalate the residual. On **every converged run**, surface the **full ledger including all dismissals + rationales** to the human (not only at the bound), so convergence-by-dismissal is visible; and **persist the durable cross-review receipt** at `openspec/changes/<name>/cross-review-receipt.md` recording the run's **verdict — explicitly whether it converged with zero unresolved findings** (a round-bound-hit run's receipt records **non-converged** and never counts as acceptance), the **adjudicated ledger**, the **coverage label**, and a **binding to the reviewed state** (the reviewed range's HEAD SHA — `git rev-parse HEAD` at review completion — plus the base B, or a deterministic digest of the range's diff; computed **non-self-referentially**, excluding the receipt file and the gate's own bookkeeping, so persisting the receipt cannot make it stale by construction — design D4) — the committed artifact the blocking pre-archive gate task (satisfied only by a converged, zero-unresolved receipt) and the fail-closed archive precondition check (design D4/D7).
- [ ] 2.5 Specify the **3-way detectable degrade classifier** (the assumed `status → ready` probe does **not** exist): **(1) capability absent** — the companion glob matches nothing, or `codex` is absent from PATH → **single-model degrade** (run A + C, label the run single-model — A + C are same-family → no cross-model coverage), **not** a hard-fail: a fresh clone must not be blocked, and "never installed" vs "corrupted cache missing the companion" cannot be distinguished, so absent-companion defaults to degrade; **(2) present but broken** — a staged probe (`codex --version`, `codex app-server --help`, or `setup --json`, each under a timeout) exits nonzero, times out, or emits malformed JSON → **surface hard as a misconfiguration**, never a silent skip; **(3) auth absent, strictly identified** — skip Pass B **only** when **all** of `node.available===true && codex.available===true && auth.loggedIn===false && auth.source==="app-server" && auth.requiresOpenaiAuth===true` hold → label the run single-model; a **null/absent `auth.requiresOpenaiAuth` is INDETERMINATE → hard-fail** (the plugin normalizes an app-server connect failure and a genuine logout into the same shape — the strict predicate conservatively rejects some genuine logged-out states, stated honestly) (design D5/R4).
- [ ] 2.6 Confirm the command is committed (un-ignored) alongside the other `.claude/commands/xtty/` tooling (`.gitignore` allowlist covers it).
- [ ] 2.7 Verify by effect **and adversarial environment** (non-vacuous — against the real `setup` probe, not `status`): run `/xtty:cross-review` on a real in-scope change (tri-pass fires, ledger merges with a consensus flag, loop converges/escalates, full ledger surfaced); then exercise **all three classifier arms** — (a) **capability absent**: move the companion out of the glob path (and/or strip `codex` from PATH) → **single-model degrade, not a hard failure** (fresh-machine semantics); (b) **present but broken**: stub a staged probe to exit nonzero / hang past the timeout / emit malformed JSON → **hard error surfaced, not a silent skip**; (c) **strict auth absence**: all five predicate fields hold → skip labeled single-model, and a `setup` payload **lacking `auth.requiresOpenaiAuth`** → indeterminate → **hard-fail**. Make the semver-resolution check **non-vacuous**: create a **throwaway second version dir** under the plugin cache (or unit-test the resolver on a synthetic version list) so it actually proves `1.0.10 > 1.0.6` numeric ordering. Confirm the commit-range substrate assertions hold/decline correctly with several changes open, with an unrelated commit interleaved (→ isolated review branch), and with a range commit lacking ownership metadata (→ **fail closed**, even when the commits sit on a per-change branch — branch location is not ownership proof). Confirm the **receipt gate** by effect: a completed run persists `cross-review-receipt.md` (verdict + adjudicated ledger + coverage label + reviewed-state binding); the gate task is satisfied **only** by a receipt recording a **converged, zero-unresolved** verdict (a round-bound-hit receipt is rejected as escalation, not acceptance); and the archive precondition **refuses** an in-scope change lacking a receipt, holding a **non-converged** one, or holding a **stale** one — **commit the receipt itself and confirm it remains current** (the non-self-referential binding exempts its own persistence commit and the gate ticks), then land any *other* post-review commit and confirm the broken HEAD/digest binding fails the archive closed — and confirm **staged and unstaged post-review edits with no commit** equally fail it closed (the clean-tree-at-archive arm; a HEAD/range binding alone cannot see them) (design D4/D7/R10).
- [ ] 2.8 Specify **model-family diversity of the soundness passes** in `.claude/commands/xtty/cross-review.md`: the two soundness passes run on **distinct model families** — Pass B on the codex CLI's configured GPT-family model (**`gpt-5.6-sol`**, design D8) at a reasoning effort suitable to deep adversarial design review (the local config's **`xhigh`**; a lower effort is defensible, but not one so shallow it misses source-traced issues), Passes A/C on **Opus** — and state that when Pass B is skipped per the 2.5 classifier, the remaining passes are same-family, so the run has **no model diversity** and its coverage label says **single-model**. Enforce and audit the pin rather than assuming local config: invoke Pass B with the model passed **explicitly** (`--model gpt-5.6-sol` — the companion's `adversarial-review` path accepts `--model` but exposes no per-call effort flag), **preflight-read the effective reasoning effort** from the codex configuration, and **record the effective model + effort in the receipt's coverage record**; an unverifiable family or effort → the run is **not** labeled full cross-model (design D8).
- [ ] 2.9 Verify model-family diversity by effect on the surfaced ledger/receipt: a full run shows the external soundness pass on the GPT-family pin, a family distinct from the Opus conformance/inline passes, with the **effective model + effort recorded in the receipt's coverage record**; a run with Pass B skipped is labeled **single-model** (no model diversity), consistent with the 2.5 degrade labels; and a run whose external model family or effort cannot be verified (e.g. a divergent local codex config) is **not** labeled full cross-model (design D8).
