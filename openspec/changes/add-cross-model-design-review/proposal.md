## Why

A single-model coherence pass is insufficient for substantive changes. Worked evidence from this session: the Opus `xtty-openspec-critic` returned **COHERENT** on `add-git-diff-wrap-toggle` while a GPT Codex adversarial review caught a real **config-ownership bug** (a base-only key modeled on `XttyProfile` instead of `XttyConfigSet`) *and* a too-shallow test plan. The two reviewers are complementary, not redundant: the critic checks **conformance** (rulebook + disk-drift) and never reads product source, while Codex checks **soundness** (approach/assumptions) and fact-checks claims against the real code. We want that cross-model check to be a repeatable, terminating ritual — plus the critic hardened to fact-check a change's claims about *existing* code. (The exemplar config bug placed a *new* field on the wrong owner — a design-ownership soundness call — which the critic's code-accuracy pass deliberately cannot catch; that class stays a cross-model catch, which is *why* the cross-model passes carry the load.)

## What Changes

- A new **cross-model review orchestrator** (`/xtty:cross-review`, main-loop-driven) fires three review passes in parallel over a change: **Pass A** = the Opus critic (conformance), **Pass B** = Codex adversarial-review (GPT soundness), **Pass C** = an *inline* Opus design-soundness pass (the diversity slice). It merges their findings into a **union ledger** tagged by source and a **2-model consensus flag** (a finding raised by both B and C = high-confidence design call).
- A **terminating convergence loop**: each round fires A∥B∥C, the caller adjudicates every finding as **fix** or **dismiss-with-recorded-rationale**, applies fixes, and re-reviews; **converged** when a round yields zero *unresolved* actionable findings from any pass — explicitly **not** "the models produce identical output." Capped at **N rounds** (default 2) with the residual ledger escalated to the human.
- **Degrade detectably, never silently**: gate the skip on Codex's own `status → ready` probe — only a genuinely-absent reviewer (unauthenticated/headless) is skipped, and that run is labeled **single-model** (Passes A and C are same-family, so a skipped B means *no* cross-model coverage). A **broken** invocation (unresolved path, module/spawn error) is **surfaced hard**, never masqueraded as a clean degrade.
- **Gated mechanically** to changes that touch product code, a spec delta beyond docs/tooling, **or the project's own review/verification/CI tooling**, run at pre-archive (optionally post-propose); the change-tail's `⟶ xtty-openspec-critic` becomes `⟶ xtty-cross-review` for those. Purely mechanical changes (docs/trackers/renames) stay critic-only. (This is *most* substantive changes, not a rare minority — an honest correction, since "has a `design.md`" is ~100%; cost is bounded by running once and degrading when Codex is absent.)
- **Pass C runs inline, not as a new standing agent** — honoring the guide's anti-speculative-roster refutation; it is required to emit Codex's JSON `review-output` schema so the two-model **consensus** is a defined join, and is promoted to a committed `xtty-design-soundness` agent only if the friction recurs.
- The **critic gains a code-accuracy pass** (Pass 4): it fact-checks `design.md`/`tasks.md` claims about **existing** symbols (file / type / field names, "mirrors `X`") against the actual source — an existing symbol absent or contradicted is a **BLOCKER**, a fuzzy/unlocatable claim is a **REVIEW**. It **does not** catch a misplaced *new* symbol (the exemplar bug's class — that stays a cross-model catch), so its value is narrow but real. Its stamp bumps **v4**, the launcher's stale delivery-check stamp is repaired **v1 → v4**, and the critic learns the new `⟶ xtty-cross-review` marker so it doesn't false-flag a qualifying tail.
- **AGENTS.md** documents the convergence protocol, the `⟶ xtty-cross-review` marker and when it replaces the critic marker, the degrade rule, and the "two reviewers cover different axes" framing; **`research/`** captures the finding with this session as the worked exemplar.

## Capabilities

### New Capabilities

- `cross-model-review`: a committed orchestrator that composes multiple review passes across two models (conformance + two-model soundness) over a design-bearing change, merges them into a union-with-consensus ledger, and drives a terminating convergence loop (findings resolved or adjudicated, capped, human-escalated), degrading gracefully when a model is unavailable.

### Modified Capabilities

- `coherence-review`: the `xtty-openspec-critic` single-change pass gains a **design-claim code-accuracy** check — fact-checking the claims a change's `design.md`/`tasks.md` make about *existing* code, BLOCKER when a claimed existing symbol is absent/contradicted, REVIEW when fuzzy (it does **not** cover misplaced *new* symbols — that stays a cross-model catch); the critic also recognizes the new `⟶ xtty-cross-review` marker.

## Impact

- **New committed tooling**: `.claude/commands/xtty/cross-review.md` (the orchestrator launcher/protocol).
- **`.claude/agents/xtty-openspec-critic.md`**: add the code-accuracy pass (Pass 4, existing-symbol scope) + `⟶ xtty-cross-review` marker awareness; bump agent `Definition: v4` and repair the launcher's stale delivery-check stamp **v1 → v4**.
- **`AGENTS.md`**: the cross-model convergence protocol, the `⟶ xtty-cross-review` change-tail marker (mechanically-gated changes) and its relation to `⟶ xtty-openspec-critic`, the detectable-degrade rule, and the committed-tooling bullet listing the new command.
- **`research/03-analysis/`**: a new capture (`cross-model-design-review-*.md`) documenting the complementary-axes finding + this session's exemplar (critic COHERENT ↔ Codex caught the config bug; and the tri-pass on *this* change where Pass C caught a high Codex missed), indexed in `research/README.md`.
- **External dependency**: the Codex plugin's companion script, already installed; the orchestrator invokes it via a **version-independent resolved path** (glob highest-version, fail loud — `${CLAUDE_PLUGIN_ROOT}` is unset in a project command) from the main loop (never a subagent — `run_in_background` strands subagents), **scoped to the change's own paths**, and degrades **only on the `ready` probe** (a broken invocation surfaces hard); **user-initiated only**, preserving Codex's `disable-model-invocation` intent.
- **No product code and no `verification-harness` delta** — dev-workflow tooling (non-UI), verified by inspection + a live run **plus an adversarial-environment step** (simulate Codex-absent vs Codex-broken) that a green author-env run cannot otherwise exercise.
- **Cost/latency**: tri-pass × up-to-N rounds is heavy, so it runs **once at pre-archive** with the mechanical gate skipping purely-mechanical changes and the degrade path bounding the worst case.
