## Why

A single-model coherence pass is insufficient for substantive changes. Worked evidence from this session: the Opus `xtty-openspec-critic` returned **COHERENT** on `add-git-diff-wrap-toggle` while a GPT Codex adversarial review caught a real **config-ownership bug** (a base-only key modeled on `XttyProfile` instead of `XttyConfigSet`) *and* a too-shallow test plan. The two reviewers are complementary, not redundant: the critic checks **conformance** (rulebook + disk-drift) and never reads product source, while Codex checks **soundness** (approach/assumptions) and fact-checks claims against the real code. We want that cross-model check to be a repeatable, terminating ritual — plus the critic hardened to fact-check a change's claims about *existing* code. (The exemplar config bug placed a *new* field on the wrong owner — a design-ownership soundness call — which the critic's code-accuracy pass deliberately cannot catch; that class stays a cross-model catch, which is *why* the cross-model passes carry the load.)

## What Changes

- A new **cross-model review orchestrator** (`/xtty:cross-review`, main-loop-driven) fires three review passes in parallel over a change: **Pass A** = the Opus critic (conformance), **Pass B** = Codex adversarial-review (GPT soundness), **Pass C** = an *inline* Opus design-soundness pass (the diversity slice). It merges their findings into a **union ledger** tagged by source and a **2-model consensus flag** (a finding raised by both B and C = high-confidence design call).
- A **terminating convergence loop**: each round fires A∥B∥C, the caller adjudicates every finding as **fix** or **dismiss-with-recorded-rationale**, applies fixes (**checkpoint-committed onto the change's contiguous commit range**, so each round re-reviews the whole change against a fixed base), and re-reviews; **converged** when a round yields zero *unresolved* actionable findings from any pass — explicitly **not** "the models produce identical output." Capped at **N rounds** (default 2) with the residual ledger escalated to the human.
- **Degrade detectably, never silently** — a **3-way classifier** on Codex's **`setup --json`** *individual* fields: (1) the Codex **capability is absent** (no companion script resolvable by the version glob, or `codex` missing from PATH) → **single-model degrade** — a fresh clone must not be blocked, and "never installed" vs "corrupted cache" is indistinguishable, so absent defaults to degrade; (2) the companion is **present but broken** — a staged probe (`codex --version`, `codex app-server --help`, `setup --json`) exits nonzero, times out, or emits malformed JSON → **surfaced hard**; (3) a **strictly-identified auth absence** — **all** of `node.available===true && codex.available===true && auth.loggedIn===false && auth.source==="app-server" && auth.requiresOpenaiAuth===true` — → skip Pass B, label the run **single-model** (Passes A and C are same-family, so a skipped B means *no* cross-model coverage). A null/absent `auth.requiresOpenaiAuth` is **indeterminate → surfaced hard**, never a skip — the plugin normalizes an app-server connect failure and a genuine logout into the same shape, so the strict predicate **conservatively rejects some genuine logged-out states** (the honest cost of not masking a broken integration). (The assumed `status → ready` probe does **not** exist — round-2 fact-check.)
- **Gated mechanically** to changes that touch product code, a spec delta beyond docs/tooling, **or the project's own review/verification/CI tooling**, run at pre-archive (optionally post-propose); the change-tail **keeps the standard `⟶ xtty-openspec-critic` task**, and the cross-review is an **enforceable, non-skippable pre-archive gate at the point-of-tick**: a **distinct blocking gate task** (separate from the critic task) that the human satisfies by running `/xtty:cross-review <change>` — the run **persists a durable receipt** (`openspec/changes/<name>/cross-review-receipt.md`, recording the verdict + the adjudicated ledger) and the task is **not ticked until that receipt exists** (a human-attestation gate, **not** an auto-firing `⟶` delegation — `/opsx:apply`'s point-of-tick grammar knows only delegate or run-inline, and a paid command that must *not* auto-fire when reached is neither, so the gate is expressed as a **receipt precondition** instead of a marker); the **archive task verifies the receipt exists and fails closed** (refuses to archive) for an in-scope change without one — so the paid Codex spend stays human-initiated *and* the gate cannot be silently skipped (a rule living outside the point-of-tick gets skipped — the repo's own measured failure class). Purely mechanical changes (docs/trackers/renames) stay critic-only. (This is *most* substantive changes, not a rare minority — an honest correction, since "has a `design.md`" is ~100%; cost is bounded by running once and degrading when Codex is absent.)
- **Pass C runs inline, not as a new standing agent** — honoring the guide's anti-speculative-roster refutation; it emits Codex's real `review-output` schema (`body`/`line_start`/`line_end`/`recommendation`, no `line`) so B and C outputs are *comparable* — the two-model **consensus** is a **heuristic confidence signal** (the same-finding match is an irreducibly semantic judgment, not a mechanical join). It is promoted to a committed `xtty-design-soundness` agent only if the friction recurs.
- The **critic gains a code-accuracy pass** (Pass 4): it fact-checks `design.md`/`tasks.md` claims about **existing** symbols (file / type / field names, "mirrors `X`") against the actual source — an existing symbol absent or contradicted is a **BLOCKER**, a fuzzy/unlocatable claim is a **REVIEW**. It **does not** catch a misplaced *new* symbol (the exemplar bug's class — that stays a cross-model catch), so its value is narrow but real — and it is **in-repo-only**: blind to external-dependency claims (e.g. the Codex plugin internals this change leans on), so it would not have caught this change's own plugin-fact errors. Its stamp bumps **v4**, and the launcher's stale delivery-check stamp is repaired **v1 → v4**.
- **AGENTS.md** documents the convergence protocol, the **receipt-gated blocking pre-archive cross-review gate** (human-initiated; the gate task is ticked only once the persisted receipt exists; archive fails closed without it; the change-tail retains `⟶ xtty-openspec-critic` as its own task), the commit-range review substrate + the new **`OpenSpec-Change: <name>` commit-trailer convention** (verifiable per-commit ownership — a validated trailer or an explicit commit-hash manifest, never branch location), the degrade rule, and the "two reviewers cover different axes" framing; **`research/`** captures the finding with this session as the worked exemplar.

## Capabilities

### New Capabilities

- `cross-model-review`: a committed orchestrator that composes multiple review passes across two models (conformance + two-model soundness) over a design-bearing change, merges them into a union-with-consensus ledger, and drives a terminating convergence loop (findings resolved or adjudicated, capped, human-escalated), degrading gracefully when a model is unavailable — each run persisting a durable receipt that a blocking pre-archive gate task and a fail-closed archive precondition check.

### Modified Capabilities

- `coherence-review`: the `xtty-openspec-critic` single-change pass gains a **design-claim code-accuracy** check — fact-checking the claims a change's `design.md`/`tasks.md` make about *existing* code, BLOCKER when a claimed existing symbol is absent/contradicted, REVIEW when fuzzy (it does **not** cover misplaced *new* symbols — that stays a cross-model catch — and it checks **in-repo** symbols only, blind to external-dependency claims).

## Impact

- **New committed tooling**: `.claude/commands/xtty/cross-review.md` (the orchestrator launcher/protocol); each run persists the **durable cross-review receipt** (`openspec/changes/<name>/cross-review-receipt.md` — verdict + adjudicated ledger) that the blocking pre-archive gate and the archive precondition check.
- **`.claude/agents/xtty-openspec-critic.md`**: add the code-accuracy pass (Pass 4, existing-symbol, in-repo-only scope); bump agent `Definition: v4` and repair the launcher's stale delivery-check stamp **v1 → v4**.
- **`AGENTS.md`**: the cross-model convergence protocol, the **receipt-gated blocking pre-archive cross-review gate** for mechanically-gated changes (a distinct blocking task ticked only on the persisted receipt; the archive step fails closed without it; the change-tail keeps `⟶ xtty-openspec-critic`; no new auto-firing `⟶` marker), the commit-range review substrate + `OpenSpec-Change:` commit-trailer convention (per-commit ownership — trailer or commit-hash manifest, never branch location), the 3-way detectable-degrade rule, and the committed-tooling bullet listing the new command.
- **`research/03-analysis/`**: a new capture (`cross-model-design-review-*.md`) documenting the complementary-axes finding + this session's exemplar (critic COHERENT ↔ Codex caught the config bug; and the tri-pass on *this* change where Pass C caught a high Codex missed), indexed in `research/README.md`.
- **External dependency**: the Codex plugin's companion script; the orchestrator invokes it via a **version-independent resolved path** (glob + **semver/numeric** highest-version; an absent companion is a **capability-absent degrade**, not a hard failure — `${CLAUDE_PLUGIN_ROOT}` is unset in a project command) from the main loop, backgrounded via the **harness's Bash `run_in_background`** (the companion's own `--background` flag is a no-op for `adversarial-review`; never a subagent — `run_in_background` strands subagents), **scoped by a contiguous commit-range substrate** (base = the parent of the change's first commit, clean tree, per-round checkpoint commits, every range commit carrying **verifiable per-commit ownership** — a validated `OpenSpec-Change: <name>` trailer or an explicit immutable commit-hash manifest, regardless of branch location (a per-change branch isolates but does **not** prove ownership) — asserted before launch and **failing closed** on any unowned range commit — focus text does *not* scope the review), and degrades via the **3-way classifier** (capability-absent or strict auth-absence degrade; present-but-broken and indeterminate auth surface hard); **human-initiated per run** (one launch authorizes the bounded N-round spend — per-run, not per-call, an owned deviation from Codex's per-call `disable-model-invocation` intent).
- **No product code and no `verification-harness` delta** — dev-workflow tooling (non-UI), verified by inspection + a live run **plus an adversarial-environment step** (simulate Codex-absent vs Codex-broken) that a green author-env run cannot otherwise exercise.
- **Cost/latency**: tri-pass × up-to-N rounds is heavy, so it runs **once at pre-archive** with the mechanical gate skipping purely-mechanical changes and the degrade path bounding the worst case.
