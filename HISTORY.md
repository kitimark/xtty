### 2026-07-07 — Local Network build-time-grant refutation + product-fix lock (research capture; informs `add-zsh-test-image`)

A graphics-VM session on the freshly-built goldens `xtty-test-zsh:26.5` (zsh) and `xtty-test:26.5` (bash) closed the open question behind `add-zsh-test-image` task 4.1 ("can the Local Network gate be neutralized at the rig / build time so the zsh graphics rig runs modal-free?"). Answer, **proven by effect from every angle: no — it cannot be granted or neutralized at build time by any means.** Captured to `research/03-analysis/local-network-privacy-forensics.md` **§8** (a dated addendum, hitting the depth bar: TN3179 read, three-tier provenance map, retired-theory fates T7–T10, re-verify-by-effect, guideline G11).

**TN3179 read in full (macOS considerations).** The `AllowedEthernet/WiFiLocalNetworkAddresses` keys are a **destination-address exemption** ("treats every address on that network as if it were not a local network address … Every program can access that address") — they gate *connections to addresses*, orthogonal to xtty's reverse-DNS *query* trigger, so they can't cover it. Apple states device managers **cannot** configure LN via MDM. The technote also documents auto-grant exceptions: `launchd` **daemons**, **root** programs, and CLI tools run over Terminal/**SSH and their children** — but *not* `launchd` agents, and attribution tracks down "**the responsible code**" (= the app).

**Refuted every way (by effect):** (1) **TCC record** — impossible: the guest's `TCC.db` has no `kTCCServiceLocalNetwork` (LN isn't a TCC service; xtty appears nowhere in TCC even when granted — the grant lives in the NetworkExtension store). (2) **`defaults write` Allowed\* ranges baked into the image** — the zsh golden bakes `10/8`+`172.16/12`+`192.168/16` (⊇ the VM's `192.168.64.x`), yet a graphics `open` of xtty **still fired the modal** (T7). (3) **NE-store pre-seed** — the decisive experiment: extract xtty's *granted* record, bake it into a fresh clone before first boot, cold-boot → `nesessionmanager` **prunes it** (count 1→0), even with xtty installed + LaunchServices-registered, while Apple system-app records (`com.apple.TV`, `com.tcltk.wish`) transplant fine; the record is `SigningIdentifier`-keyed with an **empty `DesignatedRequirement` + `AllowEmptyDesignatedRequirement=true`** (so *not* cdhash-bound — the cdhash hypothesis T9 was retracted; the killer is boot **provenance-pruning**, T8). This yielded the **three-tier provenance map**: hand-baked → pruned on boot; **implicit** (timed-out prompt) → survives boot but **re-prompts**; **explicit** (a real *Allow* click) → survives boot **and** silences (all three confirmed by cold-boot + relaunch cycles). (4) **SSH/CLI-child auto-grant** — `exec`'d xtty directly over SSH so its parent was `sshd-session: admin@notty` (ps-confirmed); the modal **still appeared** — a GUI app bundle is its own responsible code, so the exception doesn't cover it (T10). Corollary: this is **not** why headless rigs are quiet (headless = no interactive WindowServer to raise the modal; the op resolves to the default deny and the semantic tests take their graceful-degradation arms; XCUITest launches via `testmanagerd`, attributed to the app).

**The product fix, now locked (behavior-preserving + more correct).** The injected OSC 7 emitter (`App/Resources/shell-integration/zsh/xtty-integration:30`) reports the cwd authority as **`${HOST}`** = zsh's `$HOST` = **`gethostname(3)`** (no reverse-DNS). The *only* consumer of xtty's own hostname is `PaneController.localHostNames` (`App/PaneController.swift:92`), built today from `ProcessInfo.hostName` (reverse-DNS) and fed to `OSC7.decode` solely for local-vs-remote cwd classification. Building that set from **`gethostname()`** instead matches the *exact* syscall behind the shell's `$HOST` → a guaranteed match rather than a lucky short-form overlap (strictly more correct on networks where reverse-DNS yields a divergent FQDN), is behavior-preserving in the common case, and removes the reverse-DNS → kills the trigger under zsh. **Refinement to the prior §6 note:** use `gethostname()`, **not** `SCDynamicStoreCopyLocalHostName()` (the Bonjour `LocalHostName`, which can differ from `$HOST`). One call-site swap + one `localHostNames`-contains-`gethostname` unit test; still owner-deferred (the test image already gets bash for CI-parity, so no urgency), but the fix is de-risked.

**Implication for `add-zsh-test-image`:** there is no rig-level LN neutralization to build, so the divergence measurement (task 5) proceeds **headless** (the modal is graphics-only). Trackers reconciled this session: the AGENTS.md row (`(LN-gate neutralized at rig level)` → `rig LN-neutralization refuted`) + snapshot, a new Learned-refutation one-liner, the forensics §8 addendum + its `research/README.md` index line, and the task 4.1 record extended with T7/T8/T10. Session clones (`zsh-manual`, `zsh-preseed`, `zsh-sshtest`, `bash-manual`) left stopped/disposable; goldens untouched. **Note:** the working-tree `packer/xtty-test.pkr.hcl` still carries the now-triply-refuted zsh `defaults write` block (inert; bash skips it) — flagged for removal as a follow-up, not part of this capture.

## Build-infrastructure history (formerly AGENTS.md → Building, full original bullets)

- **Metal Toolchain (one-time):** SwiftTerm bundles a `.metal` shader, so even though we don't use its renderer yet, the build compiles it.
